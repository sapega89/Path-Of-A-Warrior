## 1. Скрипти (.scr) і завантаження ресурсів

**Клас al** (com/… або `al.java`): читає .scr; метод **a(index)** повертає UTF-рядок за індексом (ім'я файлу без розширення).

| Змінна | Скрипт         | Призначення                                                      |
|--------|----------------|-------------------------------------------------------------------|
| bA     | `/imgui.scr`   | Імена PNG для UI (кнопки, іконки, фон меню)                      |
| bB     | `/imgchar.scr` | Імена PNG персонажів (голови, тіла: char_head1, char_body тощо)  |
| bC     | `/imgeff.scr`  | Імена PNG ефектів                                                |
| bD     | `/imgtile.scr` | Імена тайлів (рівні: "1_01", "1_02"…)                             |
| bE     | `/edat.scr`    | Імена дата-файлів (рівні, тексти, тощо)                          |
| bG     | `/gamestr.scr` | Ігрові рядки                                                     |

**Завантаження картинки:** `d(bA.a(i))` або `d(bB.a(i))` — завантажує `"/" + string + ".png"` (ag.java, метод d(String), ~рядки 1963–1974).

### Що всередині .scr файлів (формат)

Файли **.scr** — бінарні: у них зберігається **таблиця рядків** (імена PNG, імена дата-файлів, тексти тощо). Читання через клас **al** (al.java):

1. **j.a("/imgui.scr")** — весь файл читається в масив байтів (j.java: getResourceAsStream, ByteArrayOutputStream).
2. **al.a(index)** повертає рядок за індексом:
   - Початок 4-байтного запису для індексу: `i = 2 + index * 2` (у al.java; фактично для кожного індексу читається 4 байти: start і end по 2 байти). Тобто індексна таблиця: зміщення 2, 6, 10, … (2 + index×4 байт від початку).
   - З позиції `i` читаються два 16-бітні значення (big-endian): **j** = початок блоку рядка, **k** = кінець блоку.
   - З масиву вирізається шматок `this.a[j .. k-1]`, попереду дописується 2 байти довжини (m = k − j), і цей буфер передається в **DataInputStream.readUTF()** — тобто збережено в форматі Java Modified UTF-8 (2 байти довжини + UTF-8 байти).

**Структура .scr (логічно):**

| Частина        | Опис |
|----------------|------|
| Перші 2 байти  | Можливий заголовок (наприклад, кількість записів). |
| Далі           | Індексна таблиця: для кожного індексу 0, 1, 2, … — по 4 байти: **start** (2 байти), **end** (2 байти) — зміщення в байтах до блоку даних рядка. |
| Блок даних     | Підряд збережені рядки: кожен — 2 байти довжини (big-endian) + UTF-8 байти. Позиції start/end вказують на початок такого блоку (2-байтова довжина + дані). |

Тобто **в .scr лежать тільки рядки** (текст): імена файлів без розширення (на кшталт `char_head1`, `1_01`), або тексти з gamestr.scr, або імена дата-файлів з edat.scr. Картинок у .scr немає — вони підвантажуються окремо за цими іменами як `"/" + name + ".png"`.

**Розшифровка:** у проєкті є скрипт **decode_scr.py**, який читає .scr і виводить усі рядки за індексами. Приклад:
```bash
python decode_scr.py imgchar.scr --out imgchar_strings.txt
python decode_scr.py imgui.scr --out imgui_strings.txt
python decode_scr.py imgeff.scr --out imgeff_strings.txt
```
Після запуску в проєкті з’являються файли `*_strings.txt` з таблицею «індекс → ім’я».

## 11. Вороги карти (ex[], eO[], eP, ap, au)

### Комірки карти (eO[], au)

- **ag.eO[]** — масив комірок карти (тип **au**), розмір 20. **eO[eP]** — комірка, в якій зараз стоїть гравець.
- **ag.eP** — індекс поточної комірки. Обчислення (c.java 1321):  
  `eP = (ce + 4) / 7 * (cE.b.a / 7) + (cd + 4) / 7` — тайлова координата (cd, ce — позиція камери/гравця в пікселях; крок 7).
- **au** (одна комірка): **a[0..3]** — чотири слоти (типи ворогів/об'єктів у комірці; 0 = порожньо); **b**; **c..o** — параметри комірки (рівні, стати ворогів тощо).
