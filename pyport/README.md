# pyport — Path of a Warrior на Python (етап 0, пробний перенос)

Дослівний перенос J2ME-гри з декомпільованої Java (`../*.java`, тепер у гілці `java-reference`) на pygame-ce.
Ресурси читаються з кореня репозиторію (`config.RES_ROOT`), Godot-файли не використовуються.

## Запуск

```bash
pip install -r pyport/requirements.txt
python pyport/main.py                 # вікно 480×640; New Game -> створення героя -> пролог -> Game Menu
python pyport/main.py --demo          # одразу покласти демо-сейв «HERO», якщо сейву ще немає
POW_SCALE=3 python pyport/main.py     # 720×960
python -m pytest -q pyport/tests      # тести (headless)
python pyport/tools/shot.py pyport/tools/scenarios/title.keys      # скріншоти -> pyport/shots/title/
python pyport/tools/sheet.py pyport/shots/title sheet.png          # усі кадри на одній картинці
```

**Клавіатура** (ПК → телефон, `PHASE_1_FOUNDATION.md` §5): стрілки/WASD, Enter/Space/J = OK,
Esc/Backspace = права софт-клавіша (BACK), Q/F1 = ліва; цифровий блок працює як
клавіатура телефону (8/2/4/6 = стрілки, 5 = OK). У бою: OK = удар, **1 2 3 4 5** у верхньому ряду —
п'ять слотів скілів (на телефоні це були 1/3/7/9/0; ще U/I/O/P/K), * / # (Z/X) — зілля й бомби.

**Рух лише поки тримаєш** (PORT-EXTRA `config.HOLD_TO_MOVE`, за замовчуванням увімкнено): герой іде,
поки затиснута стрілка або ліва кнопка миші, і стає, щойно відпустиш; два швидкі натискання — біг.
`POW_HOLD_TO_MOVE=0` — як на телефоні (натиснув — іде, ще раз — стоїть).

**Автонаведення на Hard** (тимчасовий PORT-EXTRA `config.AUTO_AIM_HARD`, за замовчуванням увімкнено):
в оригіналі лише на Normal герой перед ударом розвертається до найближчого ворога (`ar.f()`);
тепер і на Hard. Золото й досвід Hard не змінюються. `POW_AUTO_AIM_HARD=0` — як в оригіналі.

**Автополювання й автобій** (PORT-EXTRA `pow/game/autopilot.py`, `config.AUTO_HUNT`): **Tab** або клік
у лівий нижній кут карти вмикає й вимикає режим, у куті з'являється «AUTO». Герой сам іде до
найближчого ворога, б'є комбо, кидає навички з клавіш 1–5 і п'є зілля з * / #:
- HP-зілля, коли HP менше 30 % і лікувальну навичку не скастувати; MP-зілля, коли MP не вистачає
  на жодну навичку;
- Medium / Maximum Heal, коли HP менше 40 %, а в інший час MP на лікування не витрачається;
- Soul, коли ворогів 3+ або є генерал і аури немає; Thunder Storm / Dragon Breath / Meteor Strike
  на 3+ ворогів; Flame Twister і подібні на 2+ ворогів поруч; Lightning, коли ціль стоїть
  ~60 px попереду; Wind Slasher і подібні на генерала, на 2+ ворогів у радіусі удару або коли MP
  майже повне;
- коли впирається в стіну, обходить її; очищену кімнату покидає через відкритий вихід, спершу до
  кімнат, де ще не був.
Розмови на карті, попапи й меню паузи лишаються за гравцем. Будь-яка клавіша гравця ставить
автопілот на паузу на ~1 с. Він тисне ті самі клавіші, що й гравець, тож логіка гри лишається
оригінальною. `POW_AUTO_HUNT=1` вмикає режим одразу.
У мультиплеєрі Tab вмикає автобій (кут «AUTO»): клієнт за секунду сам шле хід 1027 з дією
`AUTO = 255`, а дію обирає бот сервера (`pow_server/battle.py cpu_choice`).

**Чит розробників** (`POW_CHEAT=1`, PORT-EXTRA `config.CHEAT`): вмикає властивість маніфесту
`GAMEVIL_CHEAT: TRUE` з оригіналу (`ag.bi`): при завантаженні сейву золото стає 555000; новий герой
отримує 500000 золота, 2000 у кожній характеристиці й усі скіли. Увага: в оригіналі чит ще й на
кожному вході в місію ставить 500000 золота і 2000 у характеристиках, і це зберігається в сейв.

**Журнал зависань** (PORT-EXTRA `pow/midp/watchdog.py`): якщо гра не робить жодного кадру 10 секунд,
стек застряглого коду дописується в `~/.path_of_a_warrior/hang.log` (там само падіння й винятки).
`POW_WATCHDOG=0` вимикає. Зависання при завантаженні карти після кількох місій (цикл у таблиці
скриптів клітинок `ag.cH`, є і в Java-оригіналі) виправлено в `c.aC()`.

**Своє золото** (`POW_GOLD=N`, PORT-EXTRA `config.GOLD`): після завантаження сейву в героя N золота,
решта не змінюється; збережеться з першим записом сейву.

**Мишка** (`pow/game/pointer.py`, клік перекладається в натискання клавіш телефону):
- титул, попап Ok — клік будь-де;
- попап Yes/No — клік лівіше центру = Yes, правіше = No (вибирає і підтверджує);
- Main Menu — стрілка ◄ / ►, клік по назві пункту = OK; колесо гортає пункти;
- Game Menu — верхня мала кнопка = вгору, велика = OK, нижня = вниз; колесо крутить карусель;
- складність — клік по Hard / Normal; герой — клік по лівій/правій голові крутить, по середній = OK;
- ім'я — клік по букві чи OK у сітці (курсор сам доходить туди стрілками і натискає OK), DEL = BACK;
- очки характеристик — клік по рядку HP / MP / ATK / DEF додає очко саме туди;
- пролог — клік = OK (увесь текст одразу), «SKIP» унизу ліворуч або Q/F1 = пропустити;
- списки меню (Management, Blacksmith, Etc, Help, Endings) — клік по рядку відкриває його;
- Options — клік по рядку вибирає його, ліва/права половина значення = ◄ / ►;
- сторінки «◄ 1/3 ►» (Help, About, Endings) — клік лівіше/правіше центру гортає;
- Blacksmith — клік по клітинці ставить туди курсор, повторний клік = OK (купити/продати/вибрати);
- Skills, Gear, Inventory, Assign Items — поки клік = OK, колесо = вгору/вниз, решта з клавіатури;
- опис місії — ◄ / ► під текстом гортає, клік по тексту = OK (попап «accept»);
- брифінг — клік = увесь рядок одразу, «SKIP» унизу ліворуч = пропустити;
- генерали — клік по рядку відкриває розмову, ◄ / ► гортає; тема розмови — клік по темі;
- карта — ліва кнопка збоку від героя = йти туди, поки кнопку тримаєш (можна вести мишкою,
  два швидкі кліки = біг); клік по самому герою = удар; **права кнопка = удар** туди, куди
  дивиться герой (напрямок — лише стрілками / рухом); клік по клітинці * / # на панелі внизу = зілля / бомба; скіли —
  лише з клавіатури (1–5); «PAUSE» унизу праворуч =
  пауза; у пауза-меню клік по рядку, колесо = вгору/вниз; у розмові на карті «SKIP» унизу
  ліворуч = пропустити;
- BACK — права кнопка миші (крім бою на карті) або клік по «BACK» внизу праворуч.

### Браузер (pygbag)

```bash
pip install -r pyport/requirements.txt
python pyport/tools/build_web.py --no-pygbag   # збирає pyport/build/web-src (код + ресурси)
python -m pygbag --ume_block 0 pyport/build/web-src   # http://localhost:8000, Ctrl+C - зупинити
```

`python pyport/tools/build_web.py` без `--no-pygbag` одразу робить статичну збірку в
`pyport/build/web-src/build/web/` (`index.html` + `web-src.apk`): цю папку можна викласти на будь-який
статичний хостинг (itch.io, GitHub Pages). Відкривати `index.html` подвійним кліком не можна - лише через HTTP.
Поруч кладеться `guide.html` — «Довідник воїна» (предмети, рецепти, секрети; джерело
`pyport/web/guide.html`), а на сторінці гри з'являється посилання на нього в правому нижньому куті.

pygbag під час збирання і в браузері завантажує рантайм з `pygame-web.github.io` (потрібен інтернет).
У консолі браузера (F12) або в терміналі сторінки `index.html#debug` має бути рядок
`RMS selftest: launch #N … OK (emscripten)`; після перезавантаження сторінки N має зрости на 1 —
це перевірка збереження в `localStorage` (сейв живе в браузері, окремо від сейву ПК-версії).

Мультиплеєр у браузері: зі звичайної збірки — Main Menu → Multiplayer (сервер — `?server=…`, як
нижче). Або окрема сторінка лише з мультиплеєром:

```bash
python pyport/tools/build_web.py --mp --no-pygbag     # pyport/build/web-mp-src (main.py = mp_main.py)
python -m pygbag --ume_block 0 pyport/build/web-mp-src   # http://localhost:8000 - сервер усередині сторінки
cd pyport && python -m pow_server --port 28200         # в іншому терміналі, для окремого сервера:
# http://localhost:8000/?server=ws://localhost:28200   - сторінка говорить із ним по WebSocket
```

Без `?server=` сервер живе в пам'яті сторінки: після перезавантаження акаунт зникає, тож клієнт
отримує 263 «токен не підходить» і повертає на екран Login. Через https сторінці потрібен `wss://`.

Особливість браузера: pygame у pygbag не вміє `pygame.image.load(BytesIO)` («can't access resource on
platform»), тому `pow/midp/graphics.py` у браузері декодує PNG через тимчасовий файл.
Перевірено в headless Chromium (pygbag 0.9.3): титул, новий герой, пролог, Game Menu, карта і бій,
сейв переживає перезавантаження сторінки.

## Правила переносу (коротко; повні — етап 1, таск 1.11)

1. **Імена.** Метод Java зберігає ім'я, якщо воно в класі (разом з `ag` і всіма його
   підкласами) одне й не збігається з полем. Інакше — суфікс сигнатури:
   `I` int, `H` short, `B` byte, `C` char, `J` long, `Z` boolean, `T` String, `M` Image,
   `G` Graphics, `A…` масив, `L<клас>` об'єкт, `v` без параметрів.
   Приклади: `x.a(Image,int,int)` → `x.a_MII`, `ag.T()` → `ag.T_v`, `ag.a_(int)` → `ag.a__I`.
   Таблиця всіх імен методів — `tools/java_names.txt`; класи й модулі — `NAMES.md`.
   Ключові слова Python отримують `_` в кінці: `as` → `as_`.
2. **Статичні поля** читаються й пишуться лише як `GameCanvas.X` (Java `ag.X`) (ніколи `self.X`, бо присвоєння
   через `self` створить поле екземпляра).
3. Кожен метод має коментар `# file.java:FROM-TO`.
4. Семантика Java: `pow/midp/jint.py` (`i8/i16/i32`, `idiv/imod`, `ushr32`). `//` замість `/`
   лише там, де обидва операнди ≥ 0 (так і позначено).
5. `# DECOMP-FIX Fn` — свідоме виправлення артефакту декомпілятора, прапорець у `config.DECOMP_FIX`.

### Карта місії

SKIP у брифінгу → `ag.y()`: HUD (кулі HP/MP, годинник місії, золото, зілля * / #), карта з
кімнат 7×7 клітинок (`c.b(int)` читає `mdat`, `c.a(int)` — виходи й хвилі ворогів кожної кімнати),
банер «Stage N». Керування як на телефоні: натиснути напрямок — герой іде, ще раз — стоїть,

виходу; дійти до краю — прокрутка в сусідню кімнату (bV = 4, `ar.k`). PAUSE (права софт-клавіша):

сейву на карті повертає в ту саму кімнату.

### Бій і вороги

Кожна кімната має список хвиль `eD` (тип, кількість): солдати 201/203 (мечники) і 202 (лучник)
з'являються по черзі, до `b` одночасно (`ar.d`, `c.b(4 int)`), з рівнем місії (`c.a(int,int)`).
ШІ ворогів (`ar.g/Y`): блукають, підходять до героя, б'ють з відстані ≤ 45, лучники стріляють
(`ar.Z/aa`). FIRE / 5 — удар героя (серія з 3–8, з кроком уперед), 1/3/7/9/0 — скіли зі слотів,
* / # — зілля (HP/MP) і бомби. Кожен удар — шкода `атака − захист`, відкидання, анімація болю;
праворуч угорі — вікно вдареного ворога: тип («Swords»), рівень і смуга HP (`ar.R/aE`).
Смерть ворога (`ar.ab`) дає досвід, золото на землі (герой підбирає, проходячи) і інколи предмет. Коли хвиля скінчилась — «Stage N Complete.» і
вихід відкривається. В останній кімнаті — генерал місії: розмова (bV = 5), дуель, у генерала свої
скіли (`ar.m`). Перемога → «Mission Success» → смуги **Total Exp** і **Time Exp** (якщо встиг
у ліміт часу; `e.n/p`, рівень героя росте прямо на смузі — «Level Up : Lv N») → розмова → `c.d(1)`.
Смерть героя → «Mission fail!» (попап 22, при рівні > 9 можна втратити предмет) → Game Menu.

**PORT-EXTRA для налагодження** (`config.NO_ENEMIES`, `config.NO_COMBAT`, за замовчуванням
вимкнені): `POW_NO_ENEMIES=1` — карта без ворогів (хвиля кімнати вважається переможеною одразу,
кімната з генералом лишається закритою), `POW_NO_COMBAT=1` — атака/скіли/зілля нічого не роблять.
Сценарії `map` / `map_mouse` запускаються з `POW_NO_ENEMIES=1` (рядок `env` у сценарії).

Створення героя (`e.java` / `ag.java` / `l.java`): Main Menu → New Game (якщо сейв є — попап 3
«saved game will be deleted») → складність (екран 29, попап 36) → герой (екран 6) → ім'я
(екран 7) → 5 очок характеристик (екран 8, попап 4) → `ax/ay/ar` записують сейв → Game Menu.
Далі `ag.l(100, 0)` запускає пролог (bV = 10): дві сторінки-картинки з текстом, що
пливе вгору, і діалоги «[Master] …» / «[ім'я героя] …» з друком по букві; кінець або SKIP → Game Menu.
На картинці SKIP гортає лише одну сторінку, на діалозі — завершує пролог (так у Java, `ag.M()`). Порядок рядків «a character for battle. /
Please select» на екрані 6 — дослівно з Java (`de - 90 - b*20`), теж варто звірити з KEmulator.

Відмінності від оригіналу (PORT-EXTRA, у кінці пакетів, оригінальний jar їх ігнорує):
- 279 повертає токен сесії, а наш клієнт додає його в 262. Оригінал після першого входу пускав за
  самим UserID; з `--legacy` сервер теж так робить (для jar в емуляторі).
- 263 зі статусом -3 означає «токен не підходить» (наш клієнт повертає на екран Login).
- 278 з новим UserID сам створює акаунт (`auto_register`): реєстрації в Gamevil Live одиночної гри
  більше немає.
- Герой з одиночної гри (таск 9.10, `pow_mp/sp_bridge.py`): у кінці кожного 262 клієнт додає героя
  із сейва одиночної гри на тому ж ПК / в тому ж браузері (рівень, HP/MP/Atk/Def, бонуси речей,
  навички та призначені слоти, зброя, обличчя, прогрес місій), як колись «Save User Data» (опкод 256).
  Без сейва — стандартний герой 1-го рівня. Після 1032 клієнт сам дописує gold / fame / exp у сейв
  одиночної гри (рівень підніметься там, коли герой наступного разу отримає досвід, `ag.H`). Слоти
  навичок береться з одиночної гри лише при першому імпорті, далі — ті, що обрано в меню Skills.
- 1026 має поле `bar_speed` (поки 0: клієнт, як оригінал, сам обирає швидкість смуги).
- Ціни навичок у шкалі MP беруться з одиночної гри (`ar.e()`: база + (рівень − 1) · приріст,
  `pow_server/sp_rules.py skill_mp`). Шкала MP 0..100 є лише в мультиплеєрі, тож ціна = частка
  від максимуму MP героя: ⌈100 · MP навички / MP героя⌉, від 1 до 100 (`skill_cost`). Шанси луту
  вигадані: серверні дані оригіналу втрачено.
- Challenge 1:1 / 2:2 і Invite An Ally (`768` → `769` мені, пуш `770` іншому гравцю, як в
  оригіналі без діалогу: приймати чи ні, вирішує Options > Invitation). Помилки, як їх показує
  клієнт: -3 «не в мережі», -4 «незареєстрований», -5 «зараз у бою», -12 «себе», -16 «відмовив».
  У 2:2 кожен гравець має CPU-союзника; в місії запрошений стає союзником (слот 2). Сервер чекає
  ходу (1027) від кожного живого гравця, а тоді шле обом той самий 1028. Хто впав, чекає 1032,
  поки інші б'ються. Хто вийшов посеред дуелі, програє; у 2:2 і в місії його бійця веде CPU.
  Клієнт сам обмежує час на вибір дії (потім Defend), тож раунд стоїть лише якщо зв'язок завис:
  тоді сесію закриває тайм-аут транспорту.
- Бот (`pow_server/bot.py`): гравець-скрипт, що приймає будь-яке запрошення і б'є звичайними
  атаками. У грі з вбудованим сервером завжди онлайн бот **RIVAL** (інші імена: змінна
  `POW_MP_BOTS=RIVAL,FOXY`), тож Challenge можна спробувати наодинці; на окремому сервері —
  `--bot RIVAL`. Бот — герой 1-го рівня без сейва одиночної гри.
- Матчмейкінг (9.15): звичайний Duel 1:1 / 2:2 (`512` режим 0 / 1) стає в чергу, клієнт тим часом
  показує «Searching for opponent». Коли приходить інший гравець того ж режиму в межах 10 рівнів
  (а після половини очікування — 20, як в оригіналі), обидва отримують 513: хто чекав — слот 0,
  новий — слот 1; у 2:2 кожному додається CPU-союзник. Якщо за хвилину (`--match-wait`) нікого
  нема, гравець отримує CPU-суперника. Поки гравець шукає, Challenge до нього дає -5. Вбудований
  у гру сервер не чекає (там немає інших людей). Solo Mission у черзі не стоїть.
- Solo Mission (`512` режим 2): я в слоті 0, CPU-союзник у 2, монстри в 1 і 3 (без навичок,
  обличчя 10). Етапів `2 + прогрес/6` (до 6) за прогресом місій одиночної гри; на останньому
  етапі замість одного монстра CPU-боєць. Між етапами 1031 → «Stage N Complete!» → 1036 → нові 514
  і 1037 (назва місії, етап) → 1038 → 1024; союзник і я відновлюємо 35 % HP. Оцінка й
  Mission Grade залежать від кількості етапів і залишку HP; gold/exp/fame — від пройдених етапів.
  У `mp_shot` сервер усередині гри бере сід із `POW_SEED`, тож сценарії повторюються.
- 2-на-2: я в слоті 0, CPU-союзник у 2 (трохи слабший), вороги в 1 і 3. Коли я падаю, клієнт
  чекає 1032 (g:683-684), тож решту бою CPU-бійці доводять на сервері; переможе команда.
- Бій і нагороди за числами одиночної гри (`pow_server/sp_rules.py`, з посиланнями на Java):
  - Шкода одного удару `ATK + баф − DEF − баф` (мінімум 1, `ar.java:293-316`). Attack — комбо
    з 3 ударів одиночної гри; смуга вирішує, скільки влучить (≥88 % три, ≥52 % два, інакше один).
    Навичка додає `ATK·рівень/aU` до кожного удару, ударів стільки, скільки кадрів удару в анімації
    (Wind 3, Storm 3, Thunder 4, Tide 6, Wave 1, Tidal 1). Лікування й Soul — формули SP.
  - Новий герой без сейва — як новий герой SP (`ag.aw`): ATK 5, DEF 4, HP 30, MP 10 + 5 очок,
    Wind Slasher і Devil Soul, Iron Claymore. Рівні за `exp.arr`, +3 очки за рівень і комплект
    Normal-речей кузні свого тіра (від 10-го рівня).
  - CPU-боєць — герой SP твого рівня (±2), очки розкладені як у тебе, ті самі навички, комплект
    кузні; переможений рахується як генерал. Монстри місій — солдати SP (`c.java:1017-1039`).
  - Вибір дії бота (`battle.cpu_choice`, вигадано: CPU оригінального сервера втрачено) — для
    CPU-бійців, монстрів і гравця на автобою (`Fighter.auto` або 1027 з дією `AUTO = 255`).
    Бот дивиться на раунд уперед тими самими числами, що й `_strike`: (1) якщо можна добити
    ворога — найдешевшою дією, що вбиває (спершу Attack); (2) лікує себе чи союзника, коли HP
    менше за шкоду двох наступних раундів, але не коли сам виграє «гонку» і не більше 3 разів за бій;
    (3) коли наступний удар летальний і ворог б'є першим (більше MP) — Defend, якщо він рятує,
    інакше Evade (крім Thunder, що пробиває Evade), не двічі поспіль; (4) Soul, лише якщо її бонус
    за раунди дії більший за пропущену атаку; (5) інакше навичка, якщо вона б'є сильніше за Attack,
    — та, що дає найбільше додаткової шкоди на 1 MP (при HP < 60 % лишає MP на лікування).
  - Нагороди: Fame = dY (рівень солдата, 2×рівень генерала/героя), EXP = 2·dY (+5 % за швидку
    місію), золото місії `h·150` (`h` 3..15 за кількістю етапів), у дуелі мішечок 20 золота з
    шансом 25 %. Поразка й провалена місія не дають нічого, як смерть в одиночній грі.
  - Вигадане (в одиночній грі цього немає): смуга удару, Defend ×0.4 і Evade 45 %, шкала MP
    (+20 за атаку, +10 за отриманий удар, +15 за стійку), оцінки D+..A+, розподіл очок героя без
    сейва (14 ATK / 4 DEF / 12 HP на 30 очок, щоб дуель тривала 6-9 раундів).
- Лут (`pow_server/loot.py`, таск 9.9): предмети з таблиць одиночної гри (`kibo` / `sungbo` /
  `shinki.arr`). За кожного переможеного ворога сервер кидає дроп одиночної гри `ar.P()`:
  боєць у дуелі як генерал (10 % дропу, з них 30 % спорядження, решта зілля 1..11), монстр місії
  як солдат (5 % / 10 %), боєць останнього етапу як бос (20 % / 60 %); тір спорядження за рівнем
  героя, як офлайн. Залишається найкращий предмет. Спорядження з шансом 20 % стає Special, 2 % Rare
  (офлайн їх дають лише Combine і Gamevil Live, тож ці два числа вигадані). Клієнт показує назву
  й «Loot!!!» (оригінальний 1032), а предмет приходить PORT-EXTRA `{id, atk, def, hp, mp}`, і клієнт
  кладе його в рюкзак одиночної гри (зілля на пояс). Якщо рюкзак повний, предмет чекає в
  `pow_mp_loot` і доходить при наступному бою чи вході. Вихід із дуелі (RSK) зараховано як поразку.
