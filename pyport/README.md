# pyport — Path of a Warrior на Python (етап 0, пробний перенос)

Дослівний перенос J2ME-гри з декомпільованої Java (`../*.java`) на pygame-ce.
Ресурси читаються з кореня репозиторію (`config.RES_ROOT`), Godot-файли не використовуються.

## Запуск

```bash
pip install -r pyport/requirements.txt
python pyport/main.py                 # вікно 480×640; New Game -> створення героя -> пролог -> Game Menu
python pyport/main.py --demo          # одразу покласти демо-сейв «HERO», якщо сейву ще немає
POW_SCALE=3 python pyport/main.py     # 720×960
python -m pytest -q pyport/tests      # тести (headless)
python pyport/tools/shot.py pyport/tools/scenarios/title.keys      # скріншоти -> pyport/shots/title/
python pyport/tools/sheet.py pyport/shots/title sheet.png          # усі кадри на одній картинці
```

**Клавіатура** (ПК → телефон, `PHASE_1_FOUNDATION.md` §5): стрілки/WASD, Enter/Space/J = OK,
Esc/Backspace = права софт-клавіша (BACK), Q/F1 = ліва; цифровий блок працює як
клавіатура телефону (8/2/4/6 = стрілки, 5 = OK). У бою: OK = удар, **1 2 3 4 5** у верхньому ряду —
п'ять слотів скілів (на телефоні це були 1/3/7/9/0; ще U/I/O/P/K), * / # (Z/X) — зілля й бомби.

**Рух лише поки тримаєш** (PORT-EXTRA `config.HOLD_TO_MOVE`, за замовчуванням увімкнено): герой іде,
поки затиснута стрілка або ліва кнопка миші, і стає, щойно відпустиш; два швидкі натискання — біг.
`POW_HOLD_TO_MOVE=0` — як на телефоні (натиснув — іде, ще раз — стоїть).

**Мишка** (`pow/game/pointer.py`, клік перекладається в натискання клавіш телефону):
- титул, попап Ok — клік будь-де;
- попап Yes/No — клік лівіше центру = Yes, правіше = No (вибирає і підтверджує);
- Main Menu — стрілка ◄ / ►, клік по назві пункту = OK; колесо гортає пункти;
- Game Menu — верхня мала кнопка = вгору, велика = OK, нижня = вниз; колесо крутить карусель;
- складність — клік по Hard / Normal; герой — клік по лівій/правій голові крутить, по середній = OK;
- ім'я — клік по букві чи OK у сітці (курсор сам доходить туди стрілками і натискає OK), DEL = BACK;
- очки характеристик — клік по рядку HP / MP / ATK / DEF додає очко саме туди;
- пролог — клік = OK (увесь текст одразу), «SKIP» унизу ліворуч або Q/F1 = пропустити;
- списки меню (Management, Blacksmith, Etc, Help, Endings) — клік по рядку відкриває його;
- Options — клік по рядку вибирає його, ліва/права половина значення = ◄ / ►;
- сторінки «◄ 1/3 ►» (Help, About, Endings) — клік лівіше/правіше центру гортає;
- Blacksmith — клік по клітинці ставить туди курсор, повторний клік = OK (купити/продати/вибрати);
- Skills, Gear, Inventory, Assign Items — поки клік = OK, колесо = вгору/вниз, решта з клавіатури;
- опис місії — ◄ / ► під текстом гортає, клік по тексту = OK (попап «accept»);
- брифінг — клік = увесь рядок одразу, «SKIP» унизу ліворуч = пропустити;
- генерали — клік по рядку відкриває розмову, ◄ / ► гортає; тема розмови — клік по темі;
- карта — ліва кнопка збоку від героя = йти туди, поки кнопку тримаєш (можна вести мишкою,
  два швидкі кліки = біг); клік по самому герою = удар; **права кнопка = удар у бік курсора**
  (герой повертається і б'є); клік по клітинці * / # на панелі внизу = зілля / бомба; скіли —
  лише з клавіатури (1–5); «PAUSE» унизу праворуч =
  пауза; у пауза-меню клік по рядку, колесо = вгору/вниз; у розмові на карті «SKIP» унизу
  ліворуч = пропустити;
- BACK — права кнопка миші (крім бою на карті) або клік по «BACK» внизу праворуч.

### Браузер (pygbag)

```bash
python pyport/tools/build_web.py --no-pygbag   # збирає pyport/build/web-src (код + ресурси, ~3.4 МБ)
python -m pygbag pyport/build/web-src           # http://localhost:8000
```

pygbag під час збирання і в браузері завантажує рантайм з `pygame-web.github.io`.
У консолі браузера (F12) має бути рядок `RMS selftest: launch #N … OK (emscripten)`;
після перезавантаження сторінки N має зрости на 1 — це перевірка збереження в `localStorage`.

## Правила переносу (коротко; повні — етап 1, таск 1.11)

1. **Імена.** Метод Java зберігає ім'я, якщо воно в класі (разом з `ag` і всіма його
   підкласами) одне й не збігається з полем. Інакше — суфікс сигнатури:
   `I` int, `H` short, `B` byte, `C` char, `J` long, `Z` boolean, `T` String, `M` Image,
   `G` Graphics, `A…` масив, `L<клас>` об'єкт, `v` без параметрів.
   Приклади: `x.a(Image,int,int)` → `x.a_MII`, `ag.T()` → `ag.T_v`, `ag.a_(int)` → `ag.a__I`.
   Таблиця всіх імен — `tools/java_names.txt` (генерує `tools/java_names.py`).
   Ключові слова Python отримують `_` в кінці: `as` → `as_`.
2. **Статичні поля** читаються й пишуться лише як `ag.X` (ніколи `self.X`, бо присвоєння
   через `self` створить поле екземпляра).
3. Кожен метод має коментар `# file.java:FROM-TO`.
4. Семантика Java: `pow/midp/jint.py` (`i8/i16/i32`, `idiv/imod`, `ushr32`). `//` замість `/`
   лише там, де обидва операнди ≥ 0 (так і позначено).
5. `# DECOMP-FIX Fn` — свідоме виправлення артефакту декомпілятора, прапорець у `config.DECOMP_FIX`.

### DECOMP-FIX, використані в етапі 0

| ID | Де | Що |
|---|---|---|
| F6 | `e.java` навігація меню, `bf` | `cM[1]=cM[1]+1; if (cM[1]+1 >= cN)` → `if (++cM[1] >= cN)`; без цього Main Menu перескакує пункти |
| F8 | `ag.L()` 1526-1546 | `switch` без `break`. Падіння крізь гілки є не лише в 3/4/5, а й у **0 і 2**: інакше на лого виконався б `bb.a(1)` і впав на `ct[7] == null` |
| F9 (новий) | `l.a(String)` 469-496 | `s = s + 1; l[s] = …` → `l[s++] = …`; буквально рядок 0 лишається старим, а останній не малюється |
| F10 (новий) | `ag.f(int,int)` 1794-1819, сітка імені | `10 * p % 14`, `17 * b / 14` → `10 * (p % 14)`, `17 * (b / 14)`; буквально курсор стрибає хаотично, а букви йдуть «драбинкою» |
| F11 (новий) | `e.T(int)` 3533-3545, курсор очок | декомпільований код передає `boolean` у колір: курсор малюється кольором 0x010101 і після першого ↑/↓ зникає; з F11 він білий, як у `e.O(1)`. **Перевірити в KEmulator** |
| F12 (новий) | `ag.h(int,int,int)`, цифри золота | декомпільований цикл `do/continue` не малює жодної цифри (рамка золота порожня); відновлено: цифри справа наліво, кома перед кожною 3-ю. **Перевірити в KEmulator** |
| F13 (новий) | `ag.y()` 892-893, старт на карті | позиція героя пишеться в `cz.a[1]`, а карта читає `cz.a[0]`; це один об'єкт лише після `ar.aC()` (`a[1] = a[0]`), тож на першій карті після запуску герой стояв би в (0, 0). З F13 перед записом `a[1] = a[0]` |
| F14 (новий) | `c.i()` 1897-1903, герой упирається в стіну | `k = aw[i]` читається до перевірки `i == -1` (індекс -1 = виняток у Java); відновлено: крок робиться в напрямку, який повернув `ar.c()` (ковзання вздовж кута) |
| F15 (новий) | `ag.a(byte[],int)` 1075-1124, опис місії з шаблоном | JD розбив `i2[1] = i3[1] = a(.., ')')` на два виклики: другий пошук перескакує наступне «(..)», довжина копії від'ємна — опис місії з шаблоном (Hellgate, Lord Eugene та ще ~45 описів) падав у `arraycopy`. З F15 одне значення на обидва |
| F6 (і в `ar.o()`) | пауза-меню на карті | той самий зламаний `--cM[1]`: ↑ з «Options» перескакував на останній пункт |

Не DECOMP-FIX, а помилка самого порту: `d.b(int,int)` робить `String.trim()`, який у Java
зрізає всі символи `<= ' '`, а `str.strip()` у Python не зрізає `'\0'` — назви предметів
закінчувались «!!!!» (гліф 0 шрифту). Виправлено в `d.py`.

### Меню (усе, крім старту місії)

Game Menu → **Management** (Attributes, Skills, Gear, Inventory, Assign Items), **Blacksmith**
(Buy, Sell, Enchant, Combine), Main Menu → **Options**, **Help**, **Endings**, **About**.
Лишається `NotPorted` лише **Gamevil Live** (мережа).

### Місії й генерали (без карти)

Структура з даних гри (`edat`: 48 — глави, 50 — місії, 55 — лорди, 56 — описи, 57 — брифінги):
**глава** (`cq`, екран 1, напр. «The Rise») → **лорд**, якому служиш (екран 2, `e.bi`) →
опис (екран 3, `ag.D`, сторінки по 6 рядків) → попап 6 «*Генерал* / Lv / Gold — accept?» →
брифінг (екран 4, `ag.am/z/ao`, `e.i/aS`: діалог із друком по букві, SKIP) → `ag.y()` = карта.
Кожен лорд у главі — окрема місія з **рівнем** `рівень героя + dz.j` і **нагородою**
`dz.h × 150` золота (×2 на Hard): у «The Rise» Lord Gabriel — Lv+1 / 450, Lord Edison — Lv+15 / 900.
Кінець місії — `c.d(int)` (`c.py`): +5 лояльності лорду, біти `dx/dy`, `cq = ds[dk]` (наступна
глава), золото, новий асортимент Blacksmith, сейв; якщо `dz.f >= 200` — кінцівка (`ag.l(i, 1)`)
і глава з таблиці; інакше розмова з генералом `dz.f` на карті (`c.g`, bV = 5).
Lord Edison має `f = 0`, тому після перемоги одразу Game Menu і глава «The Yellow».

**Visiting** (екрани 19/20) відкривається після місії (`cz.S = 1`) для знайомих генералів
(`fn/fo`): список «Name / Points», привітання (`e.a(int,int)`, файл 62), вибір теми (попап 14:
Sword / Books / Tactics / People), відповідь, «You discussed…», подарунок (`e.o()`: скіл,
характеристика, предмет — випадково, шанс = очки дружби), +5 дружби, сейв.

### Карта місії

SKIP у брифінгу → `ag.y()`: HUD (кулі HP/MP, годинник місії, золото, зілля * / #), карта з
кімнат 7×7 клітинок (`c.b(int)` читає `mdat`, `c.a(int)` — виходи й хвилі ворогів кожної кімнати),
банер «Stage N». Керування як на телефоні: натиснути напрямок — герой іде, ще раз — стоїть,
двічі швидко — біжить; стіни й межі кімнати тримають. Коли кімната зачищена, блимає стрілка
виходу; дійти до краю — прокрутка в сусідню кімнату (bV = 4, `ar.k`). PAUSE (права софт-клавіша):
Resume, Options, Save, Assign Items, Help, Exit to Menu (→ Main Menu), Exit Game. Continue після
сейву на карті повертає в ту саму кімнату.

### Бій і вороги

Кожна кімната має список хвиль `eD` (тип, кількість): солдати 201/203 (мечники) і 202 (лучник)
з'являються по черзі, до `b` одночасно (`ar.d`, `c.b(4 int)`), з рівнем місії (`c.a(int,int)`).
ШІ ворогів (`ar.g/Y`): блукають, підходять до героя, б'ють з відстані ≤ 45, лучники стріляють
(`ar.Z/aa`). FIRE / 5 — удар героя (серія з 3–8, з кроком уперед), 1/3/7/9/0 — скіли зі слотів,
* / # — зілля (HP/MP) і бомби. Кожен удар — шкода `атака − захист`, відкидання, анімація болю;
праворуч угорі — вікно вдареного ворога: тип («Swords»), рівень і смуга HP (`ar.R/aE`).
Смерть ворога (`ar.ab`) дає досвід, золото на землі (герой підбирає, проходячи) і інколи предмет. Коли хвиля скінчилась — «Stage N Complete.» і
вихід відкривається. В останній кімнаті — генерал місії: розмова (bV = 5), дуель, у генерала свої
скіли (`ar.m`). Перемога → «Mission Success» → смуги **Total Exp** і **Time Exp** (якщо встиг
у ліміт часу; `e.n/p`, рівень героя росте прямо на смузі — «Level Up : Lv N») → розмова → `c.d(1)`.
Смерть героя → «Mission fail!» (попап 22, при рівні > 9 можна втратити предмет) → Game Menu.

**PORT-EXTRA для налагодження** (`config.NO_ENEMIES`, `config.NO_COMBAT`, за замовчуванням
вимкнені): `POW_NO_ENEMIES=1` — карта без ворогів (хвиля кімнати вважається переможеною одразу,
кімната з генералом лишається закритою), `POW_NO_COMBAT=1` — атака/скіли/зілля нічого не роблять.
Сценарії `map` / `map_mouse` запускаються з `POW_NO_ENEMIES=1` (рядок `env` у сценарії).

Створення героя (`e.java` / `ag.java` / `l.java`): Main Menu → New Game (якщо сейв є — попап 3
«saved game will be deleted») → складність (екран 29, попап 36) → герой (екран 6) → ім'я
(екран 7) → 5 очок характеристик (екран 8, попап 4) → `ax/ay/ar` записують сейв → Game Menu.
Далі `ag.l(100, 0)` запускає пролог (bV = 10): дві сторінки-картинки з текстом, що
пливе вгору, і діалоги «[Master] …» / «[ім'я героя] …» з друком по букві; кінець або SKIP → Game Menu.
На картинці SKIP гортає лише одну сторінку, на діалозі — завершує пролог (так у Java, `ag.M()`). Порядок рядків «a character for battle. /
Please select» на екрані 6 — дослівно з Java (`de - 90 - b*20`), теж варто звірити з KEmulator.

## Headless-скріншоти

`tools/shot.py` запускає справжній цикл `ag.run` з `SDL_VIDEODRIVER=dummy` і віртуальним
годинником: час рухається лише через сон самого циклу (120 мс на тік у меню), тому кадри
відтворювані до пікселя. Сценарії: `title`, `gamemenu`, `mouse`, `newgame` (створення героя клавішами, з видаленням
букви і Continue після сейву), `newgame_mouse` (те саме лише мишкою), `options_help`,
`management`, `blacksmith` (новий герой + 30 000 золота: купити, продати, зачарувати, поєднати),
`menus_mouse` (меню лише мишкою), `missions` (глава → лорд → опис → брифінг → SKIP → карта → вихід;
потім Lord Edison і `win` → глава «The Yellow»), `visiting` (генерали й розмова),
`missions_mouse` (те саме мишкою), `map` (карта: рух, біг, стіна, перехід у наступну кімнату,
пауза-меню, Save, Exit, Continue назад у місію, остання кімната з генералом; без ворогів), `map_mouse`
(карта мишкою: клік збоку від героя = напрямок, PAUSE, рядки пауза-меню), `combat` (бій: удари,
вбиті вороги й золото, зілля, скіл, бомба, смерть героя → Mission fail), `victory` (сильний герой
проходить усі кімнати: розмова й дуель із генералом, Mission Success, смуги досвіду, Level Up,
розмова після перемоги, Game Menu; SKIP мишкою), `combat_mouse` (`POW_HOLD_TO_MOVE=1`: рух,
поки тримаєш кнопку миші чи клавішу, удар кліком по герою і правою кнопкою, зілля з панелі,
скіл клавішею 1). Інші сценарії натискають клавіші як на телефоні (`shot.py` ставить
`POW_HOLD_TO_MOVE=0`).
Сценарій — рядки `env NAME=VALUE`, `wait N`, `key NAME`, `hold KEY` / `release KEY`, `click X Y`,
`mousedown X Y` / `mouseup`, `rclick [X Y]`, `mclick X Y`, `wheel up|down`, `shot NAME`, `save zero`,
`gold N` (лише для тестів: золото героя), `generals N` (лише для тестів: N знайомих
генералів і дозвіл на візит), `win` (лише для тестів: виграти прийняту місію, `c.d(1)`),
`hero F N` (поле героя: `p` HP, `r` MP, `w` атака, `x` захист), `skill S ID` (вивчити скіл на слот),
`potion K ID N` (N зілль / бомб на * або #) — теж лише для тестів.
У грі `java.util.Random` має сід від часу, як у Java; `shot.py` ставить `POW_SEED=1` (PORT-EXTRA
у `jrandom.py`), тому ШІ ворогів, асортимент Blacksmith і подарунки генералів повторюються, і
тест порівнює пікселі всіх сценаріїв.
`pyport/shots/` — поточні кадри порту (база для регресійного тесту `tests/test_screens.py`).
Скріншоти KEmulator покласти в `pyport/shots_ref/<сценарій>/` з тими самими іменами й
запустити `tools/compare_ref.py`.
