# Дизайн-документ — Path of a Warrior (Godot 4)

Джерело правди: вигляд і поведінка гри. Зміни — у цьому файлі. Реалізація орієнтується на DESIGN.md; технічні деталі (шляхи, API) — TECHNICAL.md.

**Принцип:** формулювання в документі мають бути такими, щоб їх можна було однозначно перетворити на код. Назви екранів, пунктів меню, дій, полів даних, умов — відповідають ідентифікаторам і структурі в реалізації (сцени, скрипти, input map, ресурси). Один термін у документі = один відповідник у коді.

**Теги логіки:** кожній логічній одиниці відповідає один тег. Використовуються для зв’язку диздоку з кодом (коментарі, пошук, фільтрація). Нову логіку — новий тег у таблиці.

| Тег | Логіка |
|-----|--------|
| `title` | Титульний екран: порядок і кількість пунктів з M_text.png (0 Continue, 1 New Game, 2 Options, 3 Help, 4 Endings, 5 About, 6 More Games, 7 Multiplayer, 8 Exit). |

Нова логіка — новий рядок у таблиці. У коді тег можна використовувати в коментарях: `# [visiting]`, `// tag: save_load`.

**Теги елементів (сцени / стилі):** один тег = один тип візуального/сценового елемента з однаковим призначенням і стилем. У .tscn і .gd ставити коментар з тегом (наприклад `# [elem_back_btn]`); за пошуком тега визначати кількість використань: багато → один шаблон (перевикористовувана сцена або стиль .tres), мало → можна дублювати.

| Тег | Елемент | Де використовується |
|-----|---------|----------------------|
| `elem_back_btn` | Кнопка BACK (стиль: back_btn_*, один вигляд) | Усі підменю, екрани з BACK |
| `elem_list_btn` | Пункт списку / посилання (сіра рамка / біла+червоний текст) | Титул, ігрове меню, підменю (Mission, Blacksmith, …), списки |
| `elem_title_box` | Тайтл-бокс підменю (заголовок екрану) | SubmenuShell, екрани з заголовком |
| `elem_frame_v` | Вертикальна рамка (border) | Підменю, контейнери |
| `elem_frame_h` | Горизонтальна рамка (border) | Підменю, контейнери |
| `elem_table_row` | Рядок таблиці (дві ячейки з бордерами) | Visiting: кожен рядок генерала |
| `elem_table_cell` | Ячейка таблиці (бордер, текст/число) | Visiting: NameCell, RelCell |
| `elem_soft_bg` | Кнопка BACK (текстура softbg.png) | У back_btn_wrap: texture_normal = softbg.png. **Не плутати з ui_back.png** — той лише для фону (background) екрану. |

У сценах (.tscn) і скриптах (.gd) позначати відповідний вузол/блок коментарем з тегом. Пошук по проєкту за `elem_*` дає місця використання; за кількістю вирішувати: один шаблон чи копії.

## Слова та спеціальні вирази (термінологія)

Визначення термінів. У документі та в коді — одна й та сама номенклатура.

| Термін | Значення |
|--------|----------|
| **екран** | Окремий вид (view): титул, ігрове меню, підменю, таблиця генералів, діалог з генералом, License, Help тощо. Зазвичай одна сцена (.tscn) на екран. |
| **підменю** | Екран, що відкривається з пункту ігрового меню (Mission, Blacksmith, Visiting, Management): спільний шаблон (рамка, заголовок, контент, BACK). |
| **пункт меню** | Один елемент списку, на який можна перейти (наприклад «Mission», «Visiting», «To Game») або підпункт у підменю (напр. «Buy Item», «Select»). |
| **посилання (link)** | Кнопка/пункт у підменю, що веде на дію або інший екран; має текст (label) та ідентифікатор дії (action_id). |
| **BACK** | Кнопка «назад» у підменю та на екранах контенту; завжди трактується як закрити поточний екран і повернутися на попередній. |
| **Visiting** | Пункт ігрового меню та екран вибору генерала (таблиця з іменами і рівнем відносин); після вибору рядка — екран діалогу з генералом. |
| **генерал** | Персонаж, якого можна відвідати з Visiting; має ім’я, рівень відносин (число), опційно іконку; при виборі відкривається діалог. |
| **рівень відносин** | Число, що характеризує відносини гравця з генералом (наприклад 0..5); показується у другій колонці таблиці Visiting. |
| **таблиця (генералів)** | Список рядків з двома колонками: ім’я генерала, рівень відносин; кожен рядок — дві окремі ячейки з бордерами. |
| **ячейка** | Одна комірка таблиці з власним бордером (рамкою); у рядку таблиці генералів — дві ячейки (ім’я, рівень). |
| **рядок** | Один горизонтальний запис у таблиці (наприклад один генерал); у контексті меню — один пункт вертикального списку. |
| **підтвердити / обрати** | Дія вводу: вибрати поточний пункт меню або рядок (KEY_ENTER, KEY_SPACE, JOY_BUTTON_A тощо). |
| **назад / скасувати** | Дія вводу: закрити екран без вибору (KEY_ESCAPE, JOY_BUTTON_B, клік по BACK). |
| **попередній / наступний пункт** | Дія вводу: рух по списку вгору або вниз (KEY_UP/KEY_DOWN, D-pad тощо). |
| **технічне значення (клавіатура)** | Ідентифікатор клавіші в Godot: KEY_ENTER, KEY_ESCAPE, KEY_UP, KEY_DOWN тощо — не назва для користувача («Enter», «Escape»), а значення для коду та input map. |
| **технічне значення (геймпад)** | Ідентифікатор кнопки/осі: JOY_BUTTON_A, JOY_BUTTON_DPAD_UP, JOY_AXIS_LEFT_Y тощо. |
| **input map / дія (action)** | Іменована дія в проєкті (наприклад `menu_confirm`, `ui_cancel`), до якої прив’язані клавіші та кнопки геймпаду. |
| **сцена (.tscn)** | Файл, що описує дерево нод і ресурси екрану; UI-структура визначається в сценах, не збирається лише з коду. |
| **шаблон (shell)** | Перевикористовувана сцена-оболонка: однакова рамка, заголовок, місце для контенту, BACK (наприклад SubmenuShell). |
| **LinksVBox** | Контейнер у шаблоні підменю, куди кладеться список посилань (кнопки) або інший вміст (наприклад таблиця генералів). |
| **модальне вікно** | Вікно по центру екрану, що показує повідомлення-заборону (наприклад «Generals can not be visited…»). Текст + кнопка Ok/закрити. Не діалог і не алерт. |
| **алерт (alert)** | Вікно підтвердження або повідомлення: Yes/No, Ok тощо. **Не є діалогом** — це алерт. Окрема базова сцена (або варіант модального вікна з кнопками). |
| **діалог** | Лише **розмова з персонажем** (з генералом або з лордом). Діалоги з генералами і з лордами **дуже схожі** — **одна базова сцена діалогу** для обох. Вигляд згідно з Java (l.java: 210 px, 20 px між рядками, рамка). Не плутати з алертами (підтвердження, Yes/No — це алерти). |

Нові терміни — додавати в таблицю.

## Структури, об’єкти, концепти

Сутності, поля, ролі. Реалізація відповідає цим описам.

### Екрани та навігація

| Концепт | Опис | Основні «поля» / складові |
|---------|------|----------------------------|
| **Титульний екран** | Перший екран після запуску. | Список пунктів — згідно з M_text.png: 0 Continue, 1 New Game, 2 Options, 3 Help, 4 Endings, 5 About, 6 More Games, 7 Multiplayer, 8 Exit. Вибір одного пункту; кожен веде на відповідний екран або дію. |
| **Ігрове меню (головний список)** | Екран після New Game / Continue. | Вертикальний список: Mission, Blacksmith, Gamevil Live, Visiting, Management, To Game (6 пунктів). Вибір пункту → відкриття підменю або To Game. |
| **Підменю (шаблон)** | Спільний вигляд для Blacksmith, Management; для Mission — вибір сюжету і генерала/лорда; для Visiting — таблиця. | Заголовок (title), контент (LinksVBox: кнопки-посилання або таблиця), кнопка BACK. |
| **Екран вибору генерала (Visiting)** | Підменю з таблицею замість списку посилань. | Заголовок «Select», таблиця (рядки = генерали), BACK. Вибір рядка → екран діалогу з генералом. |
| **Екран діалогу з генералом** | Контент після вибору генерала з таблиці. | Текст діалогу, опційно портрет/іконка; дія «назад» → повернення до таблиці. |

### Типи екранів і типів локацій

**Типи екранів:** титул / головне меню · меню-список · підменю з посиланнями · екран-таблиця · екран-діалог · екран контенту (текст/опції) · карта світу · екран локації · бой.

**Типи локацій:** карта (світ) · місто / табір · поле битви / арена · підземелля / данж · інше.

### Дані та ігрові сутності

| Концепт | Опис | Основні «поля» / структура |
|---------|------|----------------------------|
| **Генерал** | Персонаж, якого відвідує гравець. | `id` або індекс (0..N-1), `name` (ім’я), `relationship` (рівень відносин: у Java cz.g[], short[22], 0..100 %; l.java «Friendship: 100%»), опційно `icon` (jang_1..jang_37). Пул генералів — до 37; **у Visiting показуються лише ті, хто вже запросив гравця** (логіка з Java). Назви/дані з uimenu.scr (bE.a(69)) або visit. |
| **Посилання (link) підменю** | Один пункт у списку посилань підменю. | `label` (текст кнопки), `action_id` (ідентифікатор дії для обробника). |
| **Конфіг підменю** | Набір даних для відображення підменю. | `title` (заголовок), `links` (масив посилань). Для Visiting можливий порожній `links` і контент = таблиця. |
| **Збереження гри (save)** | Стан гри для Continue. | Слот, дата; дані: прогрес, інвентар, відносини з генералами. |
| **Місія / сюжет (Mission)** | Вибір з Mission: сюжет (місія) + генерал/лорд для бою. | id місії, вартість (gB), обраний генерал/лорд (gP, gQ). Після вибору — вихід на карту (To Game) або бой. |
| **Предмет / інвентар** | Blacksmith, Management; до 25 слотів (ag.cz.Y[]). | id, назва, кількість, тип. |
| **Карта / етап** | Глава (chapter) і етап (stage) на карті. | chapter_id, map_id (ds), stage_index, stage_name (dA), spawn (b,c), battle_id, next (f,g), gold_mult, time_limit. Джерело — mission.arr, sideinfo.arr, ruler.arr. |

### UI-концепти

| Концепт | Опис |
|---------|------|
| **Рядок таблиці** | Один горизонтальний блок: дві ячейки (NameCell, RelCell), кожна з власним бордером. |
| **Ячейка** | Контейнер з рамкою (PanelContainer + StyleBox); всередині — лейбл або кнопка (ім’я генерала, число). |

### Системи та механіки

Спочатку перелік **усіх систем**, потім — **механіки**.

**Системи:** збереження/завантаження (Save, Continue) · інвентар, предмети (до 25 слотів) · Mission (вибір сюжету/місії і генерала/лорда для бою) · відносини з генералами (рівень, діалог, подарунки) · торгівля (Buy Item, Sell Item, Trade, Warehouse) · ковальство (Blacksmith: купівля, продаж; категорії Normal/Special/Rare) · складність (Difficulty) · налаштування (Options) · License · Help · Endings · вибір героя · Name · Stats · Story · карти та етапи (глави, stages) · Gamevil Live.

### 2.1 Візуальний стиль

| Аспект | Опис / вимоги |

| Аспект | Опис / вимоги |
|--------|----------------|
| **Музика** | Стиль. Екрани: титул, меню, ігровий світ. Треки по екранах. |

### 2.3 Тон та відчуття

| Аспект | Опис |

**6.4.1 Генерали в списку: обмеження, винагороди, подарунки**

- **Поява в списку (джерело правди — Java):** у таблиці Visiting показуються **лише ті генерали, які вже запросили гравця** (наприклад сказали «зайди до мене» хоча б раз у грі). Якщо генерал ніколи не запрошував гравця — **його портрет/рядок не має з’являтися в списку**. Повний пул — до 37 генералів (jang_1..jang_37), але видимий список динамічний: лише ті, для кого виконана умова «запрошення» (логіку взяти з Java-гри при порту).
- **Обмеження візиту:** у певні моменти гри візити до генералів заблоковані. Текст з оригіналу (l.java): «Generals can not be visited at this time. Try again after completing a mission.» — тобто **відвідувати генералів можна лише після виконання місії** (або в допустимий період між місіями). Якщо гравець відкриває Visiting у заборонений момент — показується **модальне вікно** з цим повідомленням (це не діалог, а вікно-заборона). Для порту: визначити з коду умову «зараз можна візити» і описувати її в §8.
- **Що дають генерали:** після успішного візиту — **підвищення рівня дружби (Friendship)**. У Java: або «Friendship increased by 5», або при максимумі «Friendship: 100%». Тобто за візит гравець отримує +5 до рівня відносин з обраним генералом (або аналогічну шкалу до 100%). Опційно генерал може давати **теми для розмови** (наприклад вибір «What do you want to talk about?» з кількома пунктами з gamestr) або **предмети/нагороди** (зв’язок з ae.aC, ae.aD у Java — визначити при порту). Підсумок для DESIGN: генерал дає (1) збільшення дружби за візит; (2) опційно — вибір теми розмови, предмета або іншої нагороди за правилами гри.
- **Принципи подарунків (джерело правди — Java):** у грі є механіка **подарунка (Gift)**. Правила:
  - **Дарувати генералу можна лише за умови дружби** (є рівень дружби з ним).
  - **І лише коли генерал сам пропонує** — тобто генерал першим щось пропонує/просить; тоді гравець може **обрати, що подарувати** цьому генералу.
  - **Подарунок** — відправка обраного предмета/золота **генералу** (одержувач — обраний генерал). З гравця списується **золото** як **податок за подарунок** (gift tax); перед відправкою — діалог підтвердження («%d gold will be paid for gift tax. Do you want to continue?» з gamestr). Після підтвердження золото списується, подарунок вважається відправленим.
  - Логіку «коли генерал пропонує», «що можна вибрати в подарунок» визначити з Java при порту; описувати в §8.

**6.6.3 Options.** Шаблон підменю; заголовок «Options»; контент — опції (гучність тощо); BACK → титул.

**6.6.4 Endings.** Шаблон підменю; заголовок «Endings»; контент — список кінцівок і текст обраної кінцівки; окрім перегляду тексту можна **програти катсцену з історією**. BACK → титул. Детально — розділ 6.7 (сюжети та ендінги).

### 6.7 Сюжети та ендінги `story` `endings`

**Джерело правди:** яку історію програвати і коли — визначає **Java-гра** (вибір індексу сюжету ej, ae.z, флаги прогресу, пройдені бої/глави). При порту логіку та таблицю умов взяти з Java.

**Екран Story (сюжет):**
- Місце в потоці: New Game → Hero → Difficulty → Name → Stats → **Story** (переісторія) → Game menu; також після проходження глави — передісторія/текст за главою.
- Показує: заголовок екрану (у Java fT[cM[0]] з gamestr), текст історії (ag.b(ga[0], ej) — gamestr, індекс 38 для ga[0]).
- Джерело текстів і **який story_id показувати**: Java-гра (gamestr.scr; для порту — decode_scr або ресурс); яку історію програвати залежить від контексту (старт гри / пройдена глава) згідно з Java.
- **Поведінка екрану:** строго з Java-гри — не додавати своїх елементів (наприклад кнопки «далі», якщо її немає в оригіналі). Перегляд тексту, прокрутка, спосіб переходу в ігрове меню — визначити з коду/екрану Java і відтворити без змін.

**Куски сюжету та умови відкриття:**
- Сюжет складається з кусків; який кусок показувати залежить від прогресу (пройдений бій, виконаний квест, досягнута локація). Приклад: пройшли цей бій → доступен цей сюжет (показується відповідний текст).
- У документі/коді має бути таблиця (або список) умов відкриття: для кожного story_id — умова (наприклад battle_won: battle_01, quest_completed: quest_02, location_reached: loc_id). Зворотний вигляд: умова → які story_id розблоковуються.
- Джерело в Java: флаги пройдених боїв/квестів, вибір індексу сюжету (ej, ae.z) за цими флагами. При дописуванні DESIGN або порту — визначити з коду/даних усі пари «умова → story_id» і зафіксувати в таблиці.

**Екран Endings (кінцівки):**
- Відкривається з титулу: вибір пункту **Endings** (індекс 4 у списку титулу). На титулі немає меню ETC — кожен пункт (Options, Help, Endings, About тощо) веде одразу на відповідний екран.
- Показує: список кінцівок (номери або назви); при виборі пункту — текст обраної кінцівки. Якщо кінцівка ще не відкрита: повідомлення «You must first complete the missions needed to view this ending.» (e.java 994).
- Джерело даних: у Java ae.z[ej], ae.z[ej+1] — зміщення в gamestr для блоку ендінгу; ej = 8 для екрану Endings. Список ендінгів і умови відкриття (за квестами) — визначити з коду/даних і прописати в §8.
- Структура «ендінг»: id, назва/номер, текст, умова відкриття (опційно), правило блокування.

### 6.8 Екран бою та інвентар

**Бой (cM[0]=20 в Java):** екран битви; показує противника, HP/MP, опційно меню дій (атака, скіл тощо). Перехід з карти при вході в комірку з ворогом. Джерело — e.java case 20, fE, fA, fD. Після перемоги: нагорода (золото, досвід), можливий перехід на наступний етап/карту (dz[dm].f, dz[dm].g). Для порту: окрема сцена бою; зберегти логіку нагород і переходів.

**Інвентар (cM[0]=4):** екран інвентаря/меню в грі; список предметів (ag.cz.Y[] — до 25 слотів), опційно екіпіровка; BACK → карта/світ. Дані — предмети (id, назва, кількість, тип) з §8. ### 6.9 Діалоги, алерти та модальні вікна `dialog` `alert` `modal` `story_window`

**Три різні типи (не плутати):**

- **Модальне вікно (заборона/попередження):** показує повідомлення, що щось заборонено (наприклад «Generals can not be visited at this time…»). Окрема базова сцен*це не діалоги**, це алерти. Окрема базова сцена (або тип модального вікна з кнопками Yes/No). Використовувати для підтверджень, питань «продовжити?» тощо.а: по центру, текст, кнопка Ok/закрити.
- **Алерт (alert):** підтвердження (Yes/No), повідомлення з Ok тощо — *
- **Діалог:** лише **розмова з персонажем** — з генералом або з лордом. **Діалоги з генералами і діалоги з лордами дуже схожі** — одна базова сцена діалогу для обох. У Java клас l (ag.cS). Вигляд: налаштувати як у Java-грі — вікно по центру (ag.dd, ag.de), ширина **210 px**, рамка (imgui, індекс 33), товщина 3–10 px, висота за контентом, текст з інтервалом **20 px** по вертикалі (l.java), кнопки внизу (40×17). Для порту: **одна базова сцена діалогу** — тільки для розмов з генералом і з лордом; стилі в .tres.

**Вікно з історією (Help / Endings / текст з gamestr):** у Java e.java l(). Вигляд: **сірий прямокутник** (ag.e() — заливка 152,152,152, внутрішня область з відступом 1 px). Розміри: **200×175** px на титулі/ландшафті (bV==2): позиція лівого верхнього кута (dd-100, de-90), тобто приблизно по центру з невеликим зміщенням; **200×120** px на інших екранах: (dd-100, de-70). Текст: контент з gamestr через d(61, index); **перенос рядків по ширині 190 px** (ag.b(arrayOfByte, 190, 0) — word wrap, результат у dp[0], dq[0]). Зліва (для екранів зі списком розділів): список пунктів dp[0][0..dq[0]], кожен рядок на висоті **20 px** (ag.de - 80 + b*20 + 3). Внизу — індикатор сторінки «N / M» (e.java a()). Для порту: панель 200×175 (або 200×120), сірий фон, текст з переносом по ширині ~190 px; опційно список тем зліва (20 px на рядок); індикатор сторінки внизу.

### 6.10 Карти та ігровий світ `maps` `stages` `chapters`

**Скільки карт:** У Java ігровий світ організований як **сторони/глави (chapters)** і **етапи (stages)** на карті. Є **до 6 сторін** (ag.ds[], ag.dt[], ag.du[], ag.dv[] — довжина 6); кількість активних сторін задається в mission.arr (v(48), ag.C()). Кожна сторона має: **ідентифікатор карти** ds[dk] (1-based), **назву** dt[dk], **зміщення даних** du[dk], **кількість етапів** dv[dk] (до 5, ag.dz — масив an[5]). Тайлова карта завантажується за ID: bd.a(ds[dk]) (c.java, ag.java); джерело тайлів — mdat_QVGA.scr → файли 1.arr … N.arr (edat.scr індекси 0..44 — 1.arr..45.arr). Тобто **унікальних тайлових карт до 45**; яка саме використовується для глави, визначає mission.arr.

**Як працюють:** Після вибору Mission → сюжет → генерал/лорд гравець потрапляє на карту обраної сторони (dk). Поточна **етап** — dm (індекс у dz[]). Для етапу зберігається (an, ag.dz[dm]): **a** — тип/група; **b, c** — позиція старту на сітці (комірки по 27×27 px); **d** — індекс тайлсету/ресурсу; **e** — id бою/події при вході в комірку; **f, g** — наступний етап або бій (якщо ≥200); **h** — множник золота; **i** — ліміт часу (сек); **j** — зміщення рівня. Назва етапу — ag.dA[dm] (з ruler.arr, v(55)). Завантаження: bi() (e.java) заповнює dz[], dA[], dB[] з v(50)=sideinfo.arr і v(55)=ruler.arr; c.a(ds[dk]) завантажує об’єкти з v(ds[dk]-1) (1.arr …); c.b(ds[dk]) — тайлова карта з mdat_QVGA. Перехід між етапами/боєм — за f, g та умовами перемоги. Прогрес відкритих сторін — ag.dw (бітова маска).

**Опис кожної карти (етапу):** Назви сторін — у dt[0..5] (з mission.arr після декодування); назви етапів — у dA[] (ruler.arr). Для порту достатньо таблиці: **chapter_id** (0..5), **map_id** (ds), **stage_index** (0..dv-1), **stage_name** (dA), **spawn** (b,c), **battle_id** (e), **next** (f,g), **gold_mult**, **time_limit**, **level_offset**. Конкретний перелік «карта 1 — назва, карта 2 — назва» можна отримати після розшифровки mission.arr, sideinfo.arr, ruler.arr (decode_scr / аналог для .arr). У проєкті є sideinfo.arr, visitgen.arr; edat_strings.txt містить 1.arr..45.arr, mission.arr (48), sideinfo.arr (50), ruler.arr (55).

**Комірки карти та сутності (модель даних, Java):** Для порту важлива модель даних карти. **Комірки (eO[]):** масив до **20** комірок (ag.eO, тип au); **eP** — індекс поточної комірки (позиція гравця/камери на сітці). Одна комірка (au): **a[0..3]** — типи ворогів/об'єктів у комірці (0 = порожньо); **b, c..n** — параметри (рівень, стани, id бою тощо). При вході в комірку значення c..n копіюються в **eD[0..11]** (c.java). Завантаження комірок з даних рівня — за форматом рівня (орієнтир: 19 байт на комірку у частині форматів). **Сутності на карті (ex[]):** масив до **7** сутностей (ag.ex, тип ap). Тип ap: **a[0], a[1]** — позиції (тип h: координати); **h** — тип сутності (201–203 = гравець/NPC, інакше ID ворога); **i, j, k, l, m** — рівень, HP, MP, ATK, DEF; **e[], f[], g[]** — анімація/стан; **B, C, D** — спрайти/зображення. Сутності створюються/оновлюються при вході в комірку згідно з a[0..3] комірки. Це модель даних для порту; візуал і геймплей руху/бою — окремо (див. §6.8, §8). Джерело: ag.java (eO, ex, eP, eD), au.java, ap.java, c.java (заповнення eD, малювання ex).

## 8. Дані та модель

**Генерали:** список імен, рівнів відносин (37 рядків Visiting). У Java: рівень відносин — cz.g[] (n.java, short[22]), діапазон 0..100 (l.java «Friendship: 100%», c.java cap 100); підписи меню (Mission, Blacksmith тощо) — fV[] з uimenu.scr (bE.a(69), індекси 30..35); іконки jang_1.png..jang_37.png. Visiting: таблиця з цими полями, вибір одного генерала → діалог. Див. 6.4.1 щодо обмежень, винагород і подарунків.

- **Поява в списку (джерело правди — Java):** у таблиці Visiting показуються **лише генерали, які вже запросили гравця** (напр. сказали «зайди до мене»). Генерал, який ніколи не запрошував — **не з’являється в списку** (портрет/рядок відсутні). Логіку «яких генералів показувати зараз» визначити з Java і перенести в порт (прапорець/умова на кшталт «запросив гравця»). Окремо: **доступність візиту** (can_visit) — у заборонений момент показується «Generals can not be visited at this time…»; джерело умови в Java.
- **Винагорода за візит:** збільшення дружби на фіксовану величину (напр. +5) або до максимуму (100%); опційно — теми розмови, предмети (ae.aC, ae.aD у Java).
- **Подарунки (джерело правди — Java):** дарувати генералу можна **лише за дружби** і **лише коли генерал сам пропонує** щось; тоді гравець обирає, що подарувати. Вартість — золото (gift tax), підтвердження діалогом. Тексти — gamestr (Gift, Gift List, gift tax). Логіку умов і вибору подарунка визначити з Java.

Збереження (Continue): механіка save/load; формат — окремо; слот, дата, прогрес, інвентар, відносини з генералами, обраний герой (cz.aB). Інші сутності: предмети, квести, складність — список і призначення.

**Сюжет:** текст історії (один або кілька блоків з gamestr). **Кусок сюжету** — id, текст (з gamestr або ресурсу), умова_відкриття (battle_id / quest_id / progress_flag). У документі або конфігу має бути **таблиця умова → story_id** (наприклад: бій X пройдено → сюжет Y доступний); при дописуванні визначити з коду/даних усі такі пари.

**Ендінг:** id, назва/номер, текст, відкритий (bool або умова за квестами). Джерело текстів — gamestr (ae.z[ej], ae.z[ej+1]); правило блокування — повідомлення до виконання квестів.
