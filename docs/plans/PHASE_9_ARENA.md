**Джерело:** окремий застосунок «Path of a Warrior Multiplayer» (`s40.kiev.ua_5426_…multiplayer…jar` у корені проєкту, MIDlet 1.0.6, сервер Gamevil `ur.gamevil.net:28200` — мертвий).

**Рішення D8 (30.10.2026):** онлайн закладаємо з першого дня.
- **9a:** сервер працює всередині гри, суперники — боти.
- **9b:** той самий сервер запускається окремо, і з'являється справжній PvP між людьми в браузері.

**Залежить від:** етапу 6 (персонаж, навички, предмети); бажано після етапу 8 (готова браузерна збірка).

## 1. Що це за гра (коротко)

Це **окрема гра з власною графікою**, а не режим основної:

| Режим | Що це |
|---|---|
| **Duel** | 1-на-1 або 2-на-2, проти комп'ютера чи людей; **Challenge** — виклик конкретного гравця |
| **Mission** | кооператив проти монстрів кількома етапами (Solo з CPU-союзником або Invite An Ally) |
| **Character** | записи, атрибути, навички, фрази, ім'я |
| **Ranking** | Fame / Duel / Mission |

**Бій покроковий.** Ходи йдуть за MP. На кожен хід — Attack / Defend / Evade / одна з 11 навичок. Влучність задає смуга таймінгу.

**Персонаж береться з одиночної гри**: рівень, HP/MP/Atk/Def з бонусами, навички, тип зброї, обличчя. Золото, слава й досвід повертаються назад.

## 2. Головна складність — серверна логіка

Клієнт оригіналу «тонкий». У ньому немає жодної формули шкоди, влучання, порядку ходів, ШІ ботів, генерації місій чи нагород: усе це рахував сервер, а його коду не збереглося. Тому все ділиться на дві частини:

| Переноситься 1:1 з Java (клієнт) | Вигадується заново (сервер) |
|---|---|
| усі екрани й меню, тексти | резолвер ходу: порядок, влучання з hit%, Defend/Evade, контратаки |
| смуга таймінгу й розрахунок hit% | ефекти 11 навичок (3/6 ударів, ігнор Def/Evd, хіли, бафи на 3 ходи) |
| програвання ходу: анімації, числа, аури | приріст MP (шкала 0..100, старт 0), вартості навичок |
| спрайти SP2, фони (32 варіанти), шрифти | ШІ ботів, генерація ботів у межах ±20 рівнів |
| формат усіх повідомлень клієнт↔сервер | місії: етапи, хвилі монстрів; нагороди, оцінки D+..A+, лут, рейтинги |

Основа для вигаданих формул — формули одиночної гри (`analysis/02`, `analysis/03`), адаптовані до покрокового бою. Баланс доводимо плейтестами.

## 3. Архітектура, що одразу готова до онлайну

```
pyport/
  pow_mp/                 # клієнт мультиплеєра (дослівно з g.java), pygame
    net/transport.py      #   Transport: LocalTransport (9a) | WebSocketTransport (9b)
  pow_server/             # СЕРВЕР — чистий Python, без pygame
    messages.py           #   повідомлення з тими самими номерами, що в оригіналі (512, 1027, 1028, …)
    codec_bin.py          #   бінарний кодек оригінального формату (+ JSON для відладки)
    engine/               #   резолвер ходу, навички, MP, ШІ ботів, місії, нагороди
    lobby.py              #   кімнати, матчмейкінг, запрошення, боти-заповнювачі
    storage.py            #   in-memory (9a) | SQLite/Postgres (9b)
    ws_server.py          #   (9b) asyncio + websockets
```

Принципи:
1. **Клієнт нічого не вирішує.** Він надсилає вибір (дія, ціль, hit%) і програє те, що прийшло. Так було в оригіналі, і так захищено від читерства.
2. **Швидкість смуги обирає сервер** і передає її клієнту (дописане поле, оригінальний клієнт зайве ігнорує). Сервер приймає лише hit% з множини, можливої для цієї швидкості.
3. **Боти — це гравці на боці сервера.** У 9a з ними весь бій, у 9b вони заповнюють матч, коли живого суперника немає.
4. **Детермінований seed** для кожного матчу → відтворювані тести й реплеї.
5. **Персонаж імпортується з сейва одиночної гри.** Сервер перевіряє стати за правилами одиночної гри (очки за рівень, межі бонусів предметів), бо сейв локальний і його можна підправити.

## 7. Ризики

- **Вигадана бойова логіка** — найбільша невизначеність: «як в оригіналі» тут перевірити нема з чим. Пом'якшення: параметри в конфігу, реплеї з seed, плейтести.
- **WebSocket у pygbag** перевірити окремим маленьким спайком на початку 9b, до розробки мережевої частини.
- **Пароль у сейві мультиплеєра** оригінал зберігав відкритим текстом і пускав без пароля після першого входу. У нашій версії так не робимо: токени (9.13).
