# План переходу на Godot

> Створено: 05.11.2026. Цей документ замінює `ROADMAP.md` як головний план, коли ми починаємо Godot-версію.
> `ROADMAP.md` і `docs/plans/PHASE_*.md` лишаються історією Python-порту.

## 0. Коротко

- **Мета:** своя гра (не порт Gamevil) на **Godot 4**, для **ПК і телефонів**, консолі пізніше.
- **Ядро пишемо з нуля.** Python-порт і звіти `docs/analysis/` — лише опис того, як грається жанр:
  кімнати, бій у реальному часі, скіли, кузня, крафт, кампанія з лордами, арена. Код, тексти,
  імена, графіку й музику робимо свої. Цифри балансу (стати, формули шкоди, досвід, ціни, дроп)
  лишаємо як є (рішення Andrey 05.11.2026), але записуємо їх своїми таблицями в `shared/data`.
- **Так, буде окремо сервер і окремо клієнт:**
  - **клієнт** — Godot-застосунок, який люди встановлюють (Steam / itch.io на ПК, Google Play і
    App Store на телефонах, пізніше консолі);
  - **сервер** — окрема програма на нашому VPS, одна на всіх гравців. Гравці її не встановлюють.
- **Сервер лишаємо на Python** (asyncio + WebSocket + SQLite, як `pyport/pow_server`), але з новим
  протоколом і новою логікою. Інфраструктурний код (акаунти, сховище, ліміти, TLS) можна взяти
  звідти, бо це наш власний код.
- **Оцінка:** ≈ 350–505 годин програмування до першого релізу на ПК і Android, плюс графіка,
  музика й тексти (окремий бюджет).

## 1. Що беремо з Python-порту, а що ні

## 2. Новий репозиторій

Рекомендую **окремий новий репозиторій** (наприклад `warrior-game`), у якому з першого коміту
немає жодного файлу Gamevil. Так чисто видно, що весь код і ресурси ваші: це важливо для магазинів
застосунків і для будь-якого спору про права. Створити репозиторій на GitHub треба вам, далі я його
підключу.

```
client/          # Godot 4 проєкт
  project.godot
  scenes/        #   title, menus, world, combat, ui
  scripts/       #   GDScript: core/, world/, combat/, items/, net/, ui/
  assets/        #   своя графіка, звук, шрифти
  tests/
server/          # Python 3.12+
  game_server/   #   accounts, sessions, profile, economy, market, arena, chat, orders
  tests/
shared/          # одне джерело правди для обох
  data/          #   items.json, recipes.json, skills.json, enemies.json, levels.json ...
  protocol/      #   опис повідомлень (JSON Schema) + тестові приклади
  vectors/       #   «золоті» тести формул: вхід → очікуваний вихід
docs/            # дизайн-документ, протокол, план
```

## 3. Сервер і клієнт: як ділимо роботу

Гра **завжди онлайн**, а **сейв тільки на сервері** (так вирішено в PR #60–#63). Тому в новій версії
сервер — **головний** («авторитетний»): він зберігає героя й сам вирішує все, що має цінність.
У Python-порті сервер зберігав те, що надіслав клієнт, без античиту. Тепер так не можна: є ринок,
обмін, PvP і рейтинги, і один зламаний клієнт зіпсує економіку всім.

| Що | Де рахується | Чому |
|---|---|---|
| Акаунт, герой, інвентар, золото, досвід, рівні | **сервер** | це «сейв», клієнт лише показує |
| Дроп після бою, нагороди за місію | **сервер** | кидок кубика на сервері, клієнт лише повідомляє «місію пройдено» |
| Кузня: купити, продати, заточити, скрафтити | **сервер** | гроші й предмети |
| Ринок, склад, сейф, подарунки | **сервер** | спільна економіка |
| Арена (PvP, 2 на 2, з ботами) | **сервер** | бій покроковий, сервер рахує раунди (як `battle.py` зараз) |
| Чат, орден, запрошення, рейтинг | **сервер** | |
| Рух, анімації, бій у реальному часі в місіях (PvE) | **клієнт** | потрібна миттєва реакція; сервер переграє журнал вводу (див. нижче) |
| Меню, налаштування, звук, керування | **клієнт** | |

**Перевірка PvE-бою.** Клієнт ніколи не надсилає «я отримав меч +5». Але й «місію пройдено» без
доказу зламаний клієнт може слати скільки завгодно, тож лише перевірки часу й кількості ворогів
**недостатньо** для гри з ринком. Тому робимо так:
1. **Старт місії видає сервер:** одноразовий квиток із зерном випадковості (`seed`), складом ворогів і
   рівнем. Один квиток — одна нагорода; квитків на годину обмежена кількість.
2. **Бій детермінований:** фіксований крок симуляції (тік), уся випадковість — лише з `seed`. Клієнт
   у кінці шле **журнал вводу** (які дії на якому тіку), а не результат.
3. **Сервер переграє журнал** тим самим кодом бою: окремий процес Godot без графіки (`--headless`)
   запускає ту саму GDScript-симуляцію. Перемога рахується, лише якщо переграш збігся.
4. **До того, як переграш готовий** (G4–G6), речі й золото з PvE прив'язані до героя: їх не можна
   продати на ринку чи передати. Ринок (G7) відкривається лише разом із переграшем.

Плюс ліміти нагород на добу й журнал підозрілих акаунтів.

**Спільні правила.** Формули (шкода, ціни, шанси) потрібні і в GDScript, і в Python. Щоб вони не
розійшлися:
1. усі числа лежать у `shared/data/*.json`, обидві сторони читають ті самі файли;
2. формули короткі, кожна має тестові приклади в `shared/vectors/`, і тести клієнта та сервера
   проганяють ті самі приклади.

### Протокол

| Канал | Для чого |
|---|---|
| **HTTPS (REST)** | вхід, реєстрація, профіль, кузня, ринок, склад: запит → відповідь |
| **WebSocket (wss://)** | те, що в реальному часі: чат, запрошення, черга матчів, бій на арені, сповіщення |

Повідомлення в JSON, кожне має `type`, `id` запиту й версію протоколу. Клієнт старої версії
отримує «онови гру», а не дивні помилки.

### Акаунти

Нинішні правила UserID (A–Z, 4–12 літер) і пароля (лише цифри) прийшли з Gamevil, їх замінюємо:
- **гостьовий вхід** одним натисканням (акаунт прив'язаний до пристрою), потім «прив'язати»;
- вхід через **Google Play Games / Apple / Steam** або email + пароль;
- Apple вимагає «Sign in with Apple», якщо є інші соцвходи, і обидва магазини вимагають кнопку
  **видалення акаунта** в самій грі.

### Де живе сервер

- Почати з одного VPS (≈ 5–20 € на місяць), Caddy або nginx для TLS, автозапуск через systemd.
- SQLite достатньо для перших сотень гравців онлайн; щоденні бекапи на інший диск. Коли буде тісно,
  перейти на PostgreSQL (шар `storage` уже відокремлений).
- Тестовий і бойовий сервери окремо; клієнт у збірці для розробки ходить на тестовий.
- Без мережі гра не стартує (рішення «завжди онлайн»). На телефоні зв'язок рветься часто, тому
  клієнт має вміти тихо перепідключатися і не губити бій, якщо зв'язок зник на кілька секунд.

## 7. Ризики

- **Схожість на оригінал.** Якщо механіки, назви чи вигляд надто близькі до Gamevil, гру можуть
  зняти з магазину. Захист: свій дизайн-документ у G0, свої числа й ресурси, нічого не копіювати з
  Python-порту дослівно; повний список — розділ «Робимо гру своєю» в [Що я б змінив у грі](https://claude.ai/artifact/MSCz8Fx7t95MK6Mtx8zQzq).
- **Дві реалізації формул** (GDScript і Python) розходяться. Захист: спільні `shared/data` і
  `shared/vectors`; бій сервер не переписує, а переграє тим самим GDScript-кодом.
- **Читерські перемоги в PvE.** Захист: квитки місій, журнал вводу і переграш на сервері; до
  переграшу PvE-нагороди не продаються.
- **Завжди онлайн на телефоні**: погана мережа дратує гравців. Захист: швидке перепідключення,
  короткі запити, зрозуміле повідомлення «немає зв'язку».
- **Контент** — найбільший ризик за часом і грошима, а не код.
- **Магазини застосунків**: політика приватності, видалення акаунта, вікові рейтинги, правила для
  внутрішніх покупок. Закладаємо в G8, а не в останній тиждень.
- **Сервер — це постійна відповідальність**: оновлення, бекапи, оплата хостингу, поки гра живе.
