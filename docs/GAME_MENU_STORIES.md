# User Stories: Game Menu — Візуальна частина

_Scope: лише те, що гравець бачить на екрані. Логіка навігації, анімації та обробка вводу — поза scope._

---

## User Story: Фон екрану меню
Як гравець я хочу бачити суцільний фон на екрані ігрового меню щоб меню виглядало завершено і не мало порожніх або прозорих областей

### Acceptance Criteria
- [ ] Текстура `ui_back.png` повністю покриває екран розміром 240×320 пікселів
- [ ] Текстура відображається тайлованою (tile mode), тобто повторюється без розривів або розтягнення
- [ ] Фон видно за всіма іншими елементами меню (знаходиться на найнижчому z-шарі)
- [ ] Жодна область екрану не залишається прозорою або чорною під фоном

---

## User Story: Горизонтальні та вертикальні бордюри
Як гравець я хочу бачити декоративні рамки по краях екрану меню щоб екран виглядав оформленим і стилістично відповідав грі

### Acceptance Criteria
- [ ] Текстура `ui_borderh.png` відображається тайлованою вздовж верхнього краю екрану
- [ ] Текстура `ui_borderh.png` відображається тайлованою вздовж нижнього краю екрану
- [ ] Текстура `ui_borderv.png` відображається тайлованою вздовж лівого краю екрану
- [ ] Текстура `ui_borderv.png` відображається тайлованою вздовж правого краю екрану
- [ ] Бордюри накладаються поверх фону (`ui_back.png`) і не перекриваються елементами вмісту меню
- [ ] Кути екрану (місця перетину горизонтального і вертикального бордюру) не мають видимих артефактів або порожніх пікселів

---

## User Story: Title box у верхній частині меню
Як гравець я хочу бачити заголовний блок у верхній частині екрану меню щоб розуміти, що знаходжуся в головному ігровому меню

### Acceptance Criteria
- [ ] Текстура `ui_titlebox.png` відображається у верхній частині екрану
- [ ] Title box вирівняний горизонтально по центру екрану (240 пікселів ширини)
- [ ] Title box розташований поверх фону та бордюрів, але не перекриває рядки меню
- [ ] Текстура відображається без розтягнення (у своїх оригінальних розмірах)

---

## User Story: Рядок попереднього пункту меню (prev)
Як гравець я хочу бачити попередній пункт меню над вибраним щоб розуміти, між якими пунктами я перебуваю

### Acceptance Criteria
- [ ] Фонова планка `bar_m.png` (89×20 px) відображається для рядка prev
- [ ] Поверх планки відображається текстовий зріз з атласу `txt_m.png` розміром 62×11 px
- [ ] Зріз атласу для prev відповідає формулі: `Y = 11 * ((selected == 0) ? 4 : selected - 1)`, де `selected` — індекс поточного вибраного пункту (0–5)
- [ ] Текстовий зріз візуально розташований всередині або поверх планки `bar_m.png`
- [ ] Рядок prev розташований вище рядка selected на екрані
- [ ] Якщо вибраний пункт — індекс 0 (Mission), рядок prev показує пункт з індексом 4 (Management)

---

## User Story: Рядок вибраного пункту меню (selected)
Як гравець я хочу бачити поточний вибраний пункт виділеним та більшим за інші щоб одразу розуміти, який пункт активний

### Acceptance Criteria
- [ ] Фонова планка `bar_b.png` (127×29 px) відображається для рядка selected
- [ ] Планка `bar_b.png` ширша та вища за `bar_m.png` (89×20 px), що візуально виділяє активний пункт
- [ ] Поверх планки відображається текстовий зріз з атласу `txt_b.png` розміром 94×18 px
- [ ] Зріз атласу для selected відповідає формулі: `Y = 18 * selected`, де `selected` — індекс поточного вибраного пункту (0–5)
- [ ] Рядок selected розташований між рядком prev (вище) та рядком next (нижче)
- [ ] Текстовий зріз `txt_b.png` більший за зріз `txt_m.png`, що підкреслює виділення

---

## User Story: Рядок наступного пункту меню (next)
Як гравець я хочу бачити наступний пункт меню під вибраним щоб орієнтуватися в структурі меню

### Acceptance Criteria
- [ ] Фонова планка `bar_m.png` (89×20 px) відображається для рядка next
- [ ] Поверх планки відображається текстовий зріз з атласу `txt_m.png` розміром 62×11 px
- [ ] Зріз атласу для next відповідає формулі: `Y = 11 * ((selected == 4) ? 0 : selected + 1)`, де `selected` — індекс поточного вибраного пункту (0–5)
- [ ] Текстовий зріз візуально розташований всередині або поверх планки `bar_m.png`
- [ ] Рядок next розташований нижче рядка selected на екрані
- [ ] Якщо вибраний пункт — індекс 4 (Management), рядок next показує пункт з індексом 0 (Mission)

---

## User Story: Ілюстрація над вибраним пунктом
Як гравець я хочу бачити унікальну ілюстрацію над виділеним пунктом меню щоб кожен пункт мав візуальний образ і меню виглядало привабливіше

### Acceptance Criteria
- [ ] Над рядком selected відображається ілюстрація розміром 90×57 px
- [ ] Ілюстрація відповідає поточному вибраному пункту: `m_illu{selected+1}.png` (наприклад, для Mission — `m_illu1.png`, для ETC — `m_illu6.png`)
- [ ] Усі шість ілюстрацій (`m_illu1.png` – `m_illu6.png`) завантажуються і відображаються коректно
- [ ] Ілюстрація відображається без розтягнення у своїх оригінальних розмірах (90×57 px)
- [ ] Ілюстрація не перекриває рядок prev та не виходить за межі екрану
- [ ] Ілюстрація розташована поверх фону та бордюрів

---

## User Story: Стрілки вгору та вниз
Як гравець я хочу бачити стрілки вгору і вниз поряд з рядками меню щоб розуміти, що список можна прокручувати в обох напрямках

### Acceptance Criteria
- [ ] Стрілка вгору (`arrow_up`) відображається над рядком prev або поряд з ним
- [ ] Стрілка вниз (`arrow_down`) відображається під рядком next або поряд з ним
- [ ] Обидві стрілки одночасно видні на екрані при будь-якому вибраному пункті (wrap-around навігація — список завжди прокручуваний)
- [ ] Стрілки розташовані в межах екрану 240×320 і не виходять за бордюри
- [ ] Стрілки відображаються поверх фону та бордюрів

# User Stories: Game Menu — Таск #4 «Wire carousel animation and navigation logic»

_Scope: навігація клавіатурою/кнопками, wrap-around, carousel slide, bounce стрілок, оновлення атласу та ілюстрації. Фокус — поведінка з точки зору гравця, конкретні перевіряємі умови._

---

## US-4.1: Навігація вниз по меню

Як гравець я хочу переміщатися вниз по пунктах меню натисканням кнопки «вниз» щоб вибрати потрібний пункт і перейти до нього

### Acceptance Criteria
- [ ] При натисканні `ui_down` / `menu_next` вибраний індекс збільшується на 1 (наприклад, 0 → 1, 1 → 2, ..., 4 → 5)
- [ ] Рядок selected відображає новий пункт одразу після завершення анімації переходу
- [ ] Рядок prev показує попередній пункт (колишній selected)
- [ ] Рядок next показує пункт після нового selected
- [ ] Повторні швидкі натискання не «стакаються» в чергу — кожен новий ввід обробляється після завершення поточної анімації або ігнорується під час неї
- [ ] Перехід не відбувається, поки активний Tween ще не завершив анімацію

---

## US-4.2: Навігація вгору по меню

Як гравець я хочу переміщатися вгору по пунктах меню натисканням кнопки «вгору» щоб повернутися до попередніх пунктів без необхідності обходити весь список знизу

### Acceptance Criteria
- [ ] При натисканні `ui_up` / `menu_prev` вибраний індекс зменшується на 1 (наприклад, 5 → 4, 4 → 3, ..., 1 → 0)
- [ ] Рядок selected відображає новий пункт після завершення анімації переходу
- [ ] Рядок prev показує пункт перед новим selected
- [ ] Рядок next показує колишній selected
- [ ] Перехід не відбувається, поки активний Tween ще не завершив анімацію

---

## US-4.3: Wrap-around навігація вниз (5 → 0)

Як гравець я хочу, щоб після останнього пункту список переходив до першого щоб меню сприймалося як кругове і я не «застрягав» на кінці списку

### Acceptance Criteria
- [ ] Коли вибраний пункт — індекс 5 (ETC) і гравець натискає «вниз», вибір переходить на індекс 0 (Mission)
- [ ] Рядок selected відображає «Mission» після переходу
- [ ] Рядок prev відображає «ETC» (індекс 5) як попередній пункт після переходу
- [ ] Рядок next відображає «Blacksmith» (індекс 1) як наступний пункт
- [ ] Анімація carousel виконується так само, як і для звичайного переходу (без пропуску або миготіння)

---

## US-4.4: Wrap-around навігація вгору (0 → 5)

Як гравець я хочу, щоб з першого пункту меню можна було перейти до останнього натисканням «вгору» щоб швидко дістатися кінця списку не проходячи крізь усі пункти

### Acceptance Criteria
- [ ] Коли вибраний пункт — індекс 0 (Mission) і гравець натискає «вгору», вибір переходить на індекс 5 (ETC)
- [ ] Рядок selected відображає «ETC» після переходу
- [ ] Рядок prev відображає «Management» (індекс 4) як попередній пункт
- [ ] Рядок next відображає «Mission» (індекс 0) як наступний пункт
- [ ] Анімація carousel виконується без артефактів

---

## US-4.5: Carousel slide анімація при переході вниз

Як гравець я хочу бачити плавну slide-анімацію рядків при переході вниз щоб зміна пункту виглядала природно і не відбувалася різким стрибком

### Acceptance Criteria
- [ ] При переході вниз рядок row1 (selected) плавно ковзає на позицію row0 (prev)
- [ ] При переході вниз рядок row2 (next) плавно ковзає на позицію row1 (selected)
- [ ] Рядок row0 (prev) зникає з екрану (ховається) до початку або в момент старту анімації
- [ ] Анімація виконується через Tween з easing EASE_IN_OUT та transition TRANS_SINE
- [ ] Тривалість анімації становить рівно 0.22 секунди (±5 мс допуск)
- [ ] Під час анімації стрілки arrow_up та arrow_down приховані і не клікабельні
- [ ] Після завершення анімації всі три рядки знаходяться на своїх кінцевих позиціях без залишкового зміщення

---

## US-4.6: Carousel slide анімація при переході вгору

Як гравець я хочу бачити плавну slide-анімацію рядків при переході вгору щоб напрямок руху відповідав напрямку навігації

### Acceptance Criteria
- [ ] При переході вгору рядок row1 (selected) плавно ковзає на позицію row2 (next)
- [ ] При переході вгору рядок row0 (prev) плавно ковзає на позицію row1 (selected)
- [ ] Рядок row2 (next) зникає з екрану до початку або в момент старту анімації
- [ ] Анімація виконується через Tween з easing EASE_IN_OUT та transition TRANS_SINE
- [ ] Тривалість анімації становить рівно 0.22 секунди (±5 мс допуск)
- [ ] Під час анімації стрілки arrow_up та arrow_down приховані
- [ ] Після завершення анімації всі три рядки знаходяться на своїх кінцевих позиціях без залишкового зміщення
- [ ] Напрямок руху рядків протилежний до напрямку «вниз» — рядки ковзають вниз, а не вгору

---

## US-4.7: Стрілки зникають під час анімації та з'являються після

Як гравець я хочу, щоб стрілки ховалися під час переходу між пунктами щоб вони не заважали сприйняттю анімації і не створювали враження подвійного натискання

### Acceptance Criteria
- [ ] В момент початку carousel анімації (старт Tween) стрілки arrow_up та arrow_down стають невидимими (`visible = false`)
- [ ] Стрілки залишаються прихованими протягом усіх 0.22 секунди анімації
- [ ] Одразу після завершення Tween стрілки знову стають видимими
- [ ] Bounce-анімація стрілок відновлюється після їх появи без «стрибка» до початкової позиції

---

## US-4.8: Arrow bounce анімація (sine wave)

Як гравець я хочу бачити стрілки, що плавно підстрибують у спокійному стані щоб меню виглядало живим і підказувало, що навігація доступна

### Acceptance Criteria
- [ ] Стрілка arrow_up рухається вгору-вниз за синусоїдою: зміщення по Y = `sin(t * 2.0 * TAU) * 2` пікселі
- [ ] Стрілка arrow_down рухається вниз-вгору за тією ж синусоїдою (протилежна фаза або той самий напрямок за спекою — стрілка вниз рухається від центру вниз)
- [ ] Анімація є безперервною (looping) під час відображення стрілок
- [ ] Амплітуда bounce не перевищує 2 пікселі у кожному напрямку від початкової позиції
- [ ] Bounce не зупиняється між навігаційними переходами (відновлюється після кожного переходу)
- [ ] Стрілки не виходять за межі екрану під час bounce

---

## US-4.9: Оновлення atlas region при зміні вибору

Як гравець я хочу, щоб текстовий зріз атласу автоматично змінювався при переході між пунктами щоб кожен рядок показував правильну назву пункту

### Acceptance Criteria
- [ ] Після кожного переходу region рядка selected оновлюється до `Rect2(0, 18 * selected, 94, 18)` з атласу `txt_b.png`
- [ ] Після кожного переходу region рядка prev оновлюється до `Rect2(0, 11 * prev_index, 62, 11)` з атласу `txt_m.png`, де `prev_index = (selected == 0) ? 4 : selected - 1`
- [ ] Після кожного переходу region рядка next оновлюється до `Rect2(0, 11 * next_index, 62, 11)` з атласу `txt_m.png`, де `next_index = (selected == 4) ? 0 : selected + 1`

  Граничні випадки:
- [ ] При selected = 0 (Mission): prev показує індекс 4 (Management), next показує індекс 1 (Blacksmith)
- [ ] При selected = 5 (ETC): prev показує індекс 4 (Management), next показує індекс 0 (Mission) — тобто `next_index = (selected == 4) ? 0 : selected + 1` повертає 6 якщо не оброблено wrap; переконатись що для selected=5 next показує 0
- [ ] Оновлення регіону відбувається до старту Tween, щоб під час анімації рядки вже містили правильний текст
- [ ] Жоден рядок після переходу не показує назву, що відповідає попередньому стану

---

## US-4.10: Ілюстрація змінюється при зміні вибору

Як гравець я хочу бачити нову ілюстрацію кожного разу, коли змінюю вибраний пункт щоб ілюстрація завжди відповідала поточному пункту і підсилювала його сприйняття

### Acceptance Criteria
- [ ] Після переходу на пункт з індексом `selected` відображається ілюстрація `m_illu{selected+1}.png`
  - selected = 0 → `m_illu1.png`
  - selected = 1 → `m_illu2.png`
  - selected = 2 → `m_illu3.png`
  - selected = 3 → `m_illu4.png`
  - selected = 4 → `m_illu5.png`
  - selected = 5 → `m_illu6.png`
- [ ] Зміна ілюстрації відбувається після завершення carousel анімації (не в момент натискання), щоб не було видно «не ту» картинку під час ковзання рядків
- [ ] Попередня ілюстрація не залишається видимою після зміни вибору
- [ ] Ілюстрація відображається у розмірі 90×57 px без розтягнення
- [ ] При wrap-around переходах (0→5, 5→0) ілюстрація також коректно оновлюється

# User Stories: Game Menu — Таск #5 «Menu item actions»

_Scope: що відбувається після підтвердження вибору пункту меню. Фокус — очікування гравця та перехід до наступного екрана/підменю._

---

## US-5.1: Mission

Як гравець я хочу, щоб вибір «Mission» запускав послідовний флоу вибору місії щоб потрапити в бій через зрозумілі кроки

### Acceptance Criteria
- [ ] Після підтвердження «Mission» відкривається екран вибору місії (mission selection list)
- [ ] Після вибору місії відкривається екран вибору лорда (lord select)
- [ ] Після вибору лорда відображається briefing, після якого стартує ігрова сесія (game scene)

---

## US-5.2: Blacksmith

Як гравець я хочу, щоб вибір «Blacksmith» відкривав підменю ковальні щоб мати доступ до Buy, Sell, Enchant та Combine

### Acceptance Criteria
- [ ] Після підтвердження «Blacksmith» відкривається підменю з 4 пунктами: Buy, Sell, Enchant, Combine
- [ ] Кожен пункт підменю є окремим вибором і не активує одразу інший екран
- [ ] Кнопка «Назад» у підменю повертає до головного ігрового меню

## US-5.3: Gamevil Live
