## 0. TL;DR

* «Lord id» з попередніх документів (`ag.ds[ag.dk]`, `ag.cg`) насправді **id області/карти** (1..45, назви з `mission.arr`: "The Rise", "Hellgate"…). Він же індекс у `mdat_QVGA.scr` (`N.MAP`) і в `edat.scr` (`N.arr`). Лорди-замовники (Lord Gabriel…) — це `ruler.arr`, поле `dz[dm].a`.
* Карта = сітка `W×H` тайлів 27×27, де `W = 7·RW + 2`, `H = 7·RH + 2`: **кімнати 7×7** + спільна рамка в 1 тайл. Для всіх 45 карт `(W-2)%7 == (H-2)%7 == 0`.
* `.MAP` = `[W][H][P][P байт палітри][4 шари по W·H байт][необов'язковий блок подій]`. Шари: 0 ground, 1 overlay, 2 objects (руйнівні), 3 attributes (bit0 = solid, bit1 = foreground). Події — лише опкод 0: «у місії №k поставити лучника (тип 202) на цей тайл».
* `.arr` = 20 байт заголовка `[19, 1×19]` + на кожну місію `RW·RH` записів по 19 байт (виходи кімнати, ліміт живих ворогів = 3, черга спавну з 6 пар, id генерала-події).
* Тайл id `t` (1..240) → PNG `"{(t-1)//16+1}_{(t-1)%16+1:02d}.png"` (`imgtile.scr` = "1".."15"). Усього на картах використано 231 з 240 тайлів.
* Камера **не скролиться**: екран показує 9×9 тайлів (кімната + кільце) = 243×243 px, вікно карти на екрані — `(0,16)-(240,259)`, зсув джерела `cc = (1,0)`. Перехід між кімнатами — миттєвий flip на 7 тайлів (189 px).
* Рух гравця — **тільки 4 напрямки, по події натискання** (keyPressed без keyReleased): натиснув — іде безперервно; той самий напрямок ще раз — стоп; подвійне натискання — ривок. Швидкість 6 px/тік (діагоналі 5 px), ривок 24 px/тік × 3 тіки. Тік = 120 мс за замовчуванням (опція 250/180/120/90/50 мс).
* Колізія: бокс `[x-12, x+12] × [y-20, y+6]` проти тайлів з `attr&1` або з об'єктом у шарі 2; плюс жорсткий кламп у межах поточної кімнати; авто-обхід кутів (`ar.c`).
* Цикл кімнати: вхід → «Stage N» → вороги заходять з відкритих країв (≤3 живих, по одному за тік) → усі мертві й черга порожня → «Stage N Complete.» → (діалог з генералом, якщо байт 18 кімнати ≠ 0) → блимаючі стрілки на відкритих краях → вихід. Перемога — коли кімнату, в якій з'явився цільовий генерал (`dz[dm].e`), очищено. Поразка — HP = 0.
* Знайдено 3 місця, де декомпільований код **не може** бути буквальним (доведено даними): `W/7*H/7` треба читати як `(W/7)*(H/7)` (c.java:1090, 1321); порядок обчислення в c.java:1904-1907; посилання в хеш-таблиці подій (c.java:1185-1189). Деталі в §9.

## 1. Як це виглядає для гравця

1. У меню «Missions» гравець обирає **область** (до 6 на «главу» `cq`, `ag.C()` ag.java:1043-1062), потім **місію** цієї області (`e.bi()` e.java:3569-3603), читає брифінг (`ag.D()` ag.java:1064-1073) і підтверджує («Do you want to accept this mission?», l.java:664-673 — показує ім'я цільового генерала, `Lv cz.l + dz.j` і золото).
2. Діалог гравця з лордом-замовником (`dG = 0`, `event1.scr`, l.java:109-113 → e.java:1266-1310), потім екран завантаження (`loading.png`, ag.java:1026-1027) і гравець опиняється у **стартовій кімнаті** (стартовий тайл з `sideinfo.arr`). Зверху з'являється «Stage 1».
3. Кімната займає майже весь екран (7×7 тайлів + видно по одному тайлу сусідніх кімнат/рамки). Вороги-мечники **заходять з відкритих країв кімнати**, одночасно не більше 3; іноді «загін» з 3 мечників (тип 203). На стінах/вежах стоять **лучники** (202), вони не рухаються і стріляють. Глечики/ящики (шар об'єктів) розбиваються і можуть дати предмет/золото. Коли в черзі доходить до **генерала** — гра зупиняється на діалог (`event2.scr`), потім бій.
4. Коли всі (крім лучників) убиті і черга порожня: «Stage N Complete.»; інколи — діалог з генералом-подією (дружба +5). Потім на відкритих краях **блимають стрілки** (arrow0..3). Гравець виходить через край → миттєвий перехід у сусідню кімнату → «Stage N+1».
5. **Перемога**: очищено кімнату, де з'явився цільовий генерал місії → «Mission Success» → «Gold Acquired!» → «Total Exp» → (якщо час < ліміту) «Time Exp». **Поразка**: HP = 0 → анімація смерті → «Mission fail!» (можлива втрата спорядження). Вихід через паузу.
6. HUD: таймер MM:SS зліва вгорі, лічильник убитих справа вгорі (або ім'я/рівень/HP ворога, якого щойно вдарили), кулі HP (ліворуч) і MP (праворуч) внизу, 2 швидкі предмети (`*`, `#`), права софт-клавіша «PAUSE».

Мінікарти **немає** (не знайдено жодного коду малювання огляду карти; впевненість висока).

## 2. Бінарні формати (перевірено)

### 2.1 `.scr` — таблиця рядків (`al.java` 11-31)

* `entry(i)`: `start = u16le(2 + 2i)`, `end = u16le(4 + 2i)` (записи перекриваються: кінець i = початок i+1). Рядок = байти `[start, end)`, читаються як Java modified-UTF-8 (`readUTF` з доданою довжиною).
* **Увага**: `JAVA_REFERENCE.md` §1 пише «big-endian» і «4 байти на індекс» — це неточно. Код (`al.java:13-14`) читає **little-endian** і крок **2 байти** (decode_scr.py робить правильно).

### 2.3 `N.MAP` (`c.b(int)` c.java:1128-1167)

Файл читається як масив **беззнакових байтів** (`o.a[k] = byte & 0xFF`, c.java:1137-1138).

| Зміщення | Розмір | Поле | Примітка |
|---|---|---|---|
| 0 | 1 | `W` (`o.b.a`) | ширина в тайлах (9..37) |
| 1 | 1 | `H` (`o.b.b`) | висота в тайлах (9..72) |
| 2 | 1 | `P` (`o.b.c`) | довжина «палітри» |
| 3 | P | палітра | **відсортований** список усіх різних значень у шарах 0,1,2 плюс `v+1` для кожного об'єкта `v` шару 2 (включно з 0). Перевірено для 45/45. Гра її **пропускає** (`i = 3 + c`, c.java:1144) — це лише список для передзавантаження. |
| 3+P | W·H | шар 0 **ground** (`o.c`) | id тайла, row-major `y*W+x` |
| 3+P+WH | W·H | шар 1 **overlay** (`o.d`) | id тайла або 0 |
| 3+P+2WH | W·H | шар 2 **objects** (`o.e`) | 0 або **непарний** id руйнівного об'єкта (97..131); `id+1` = кадр «розбитий» |
| 3+P+3WH | W·H | шар 3 **attributes** (`o.f`) | значення 0..3: `bit0 (1)` = непрохідно, `bit1 (2)` = overlay малюється поверх персонажів (foreground) |
| 3+P+4WH | 1 | `count` подій | лише якщо файл довший (c.java:1155) |
| +1 | 2 | `total` (u16le) | пропускається (`i += 2`, c.java:1157); дорівнює сумі `4+len` усіх записів (перевірено) |
| далі | — | `count` записів | кожен: `x`(1) `y`(1) `len`(u16le) `body[len]` (c.java:1159-1163) |

`body` = послідовність команд по 3 байти `(op, p1, p2)` (інтерпретатор `c.c(int,...)` c.java:918-926):
* `op 0`: якщо `ag.dm == p1-1` (номер місії в області, 1-based) → `c.b(p2+200, x, y, 4)` — спавн NPC типу `200+p2`. **У всіх 747 командах `p2 == 2` → тип 202 = лучник**. Інші опкоди повернули б 0 і зациклили б інтерпретатор (не трапляються).
* Події шукаються при вході в кімнату для 7×7 тайлів її інтер'єру (`c.g()` c.java:894-916, виклик c.java:1384). Хеш-таблиця `ag.cH[50]`, ключ `(x+y)&7`, переповнення з індексу 8 (c.java:1169-1195). Тільки **перший** запис з даними `(x,y)` виконується (break, c.java:908).
* Дані: 2 події поза картою (map 21 `(35,9)`, map 44 `(48,37)`) — ніколи не спрацюють; 33 лучники стоять на `attr&1` (на стінах — це задум); 1 команда для неіснуючої місії (map 1 `(1,11)` місія 5).

Кількість місій у файлі `(size-20)/(R·19)` збігається з `dv` у `mission.arr` для всіх 45 областей (разом **102 місії** — та сама константа 102 у формулі прогресу c.java:1459).
Виходи — **орієнтований граф** кімнат: перевірено, що для всіх 102 місій кімната з цільовим генералом досяжна від стартової, а «виходи за межі карти» є лише в кімнатах цільового генерала (там вони потрібні тільки як краї для спавну). Тупикових кімнат, які можна відвідати до цілі, немає.

### 2.6 Тайл id → PNG / атлас (c.java:1221-1311)

* `cJ[240]` — відображення `tileId-1 → слот+1` у масиві `ag.bT[]` (кеш тільки потрібних картинок).
* Ім'я: `bD.a(g) + "_" + (f<9 ? "0" : "") + (f+1)`, де `g = (id-1) >> 4`, `f = (id-1) & 15` (c.java:1293-1298) → **`1_01.png` … `15_16.png`**, кожен окремий PNG 27×27, малюється цілком (`ag.c(img,0,0,x,y,27,27)`).
* Для Godot: один атлас 16 колонок × 15 рядків, `atlas_coords = ((id-1) % 16, (id-1) / 16)`.
* Об'єкти: інтактний `v` (непарний) і розбитий `v+1` — сусідні кадри; HP об'єкта 41 для `v ∈ {101, 113}`, інакше 21 (c.java:1259-1267). Використані об'єкти: 97,101,103,105,109,111,113,115,117,119,121,123,125,129,131 (групи 7, 8, 9).
* **PNG-файлів у цій копії проєкту немає** (`find -iname '*.png'` → 0). Перевірити картинки неможливо; їх треба витягти з оригінального JAR.

### 2.10 Референсний парсер (запущено успішно: `python3 -I powmap.py /home/claude/pow 1`)

```python
#!/usr/bin/env python3
"""Reference parser for Path of a Warrior map data (N.MAP, N.arr, *.scr string tables).
Usage: python3 -I powmap.py <data_dir> [map_id]
"""
import sys, os

TILE = 27          # px
ROOM = 7           # tiles per room side (interior)

def read_scr(path):                       # al.java 11-31
    d = open(path, 'rb').read()
    out, idx = [], 0
    while True:
        i = 2 + idx * 2                   # entries overlap: end(i) == start(i+1)
        if i + 4 > len(d):
            break
        start = d[i] | d[i + 1] << 8      # little-endian u16
        end = d[i + 2] | d[i + 3] << 8
        if start >= end or end > len(d):
            break
        out.append(d[start:end].decode('utf-8', 'replace'))
        idx += 1
    return out

def tile_png(tile_id, imgtile):           # c.java 1293-1298
    g, f = (tile_id - 1) >> 4, (tile_id - 1) & 15
    return f"{imgtile[g]}_{f + 1:02d}.png"

def parse_map(path):                      # c.b(int), c.java 1128-1167
    d = open(path, 'rb').read()
    W, H, P = d[0], d[1], d[2]
    palette = list(d[3:3 + P])            # sorted distinct ids (incl. 0 and obj+1); skipped by the game
    o, n = 3 + P, W * H
    names = ('ground', 'overlay', 'object', 'attr')
    layers = {nm: d[o + k * n:o + (k + 1) * n] for k, nm in enumerate(names)}
    i = o + 4 * n
    events = []
    if len(d) > i:                        # optional event block
        count = d[i]
        total = d[i + 1] | d[i + 2] << 8  # skipped by the game; == sum(4+len)
        i += 3
        for _ in range(count):
            x, y = d[i], d[i + 1]
            ln = d[i + 2] | d[i + 3] << 8
            body = d[i + 4:i + 4 + ln]
            cmds = [tuple(body[k:k + 3]) for k in range(0, ln, 3)]  # (0, mission_no_1based, npc_type-200)
            events.append(dict(x=x, y=y, cmds=cmds))
            i += 4 + ln
    assert i == len(d), (path, i, len(d))
    return dict(W=W, H=H, palette=palette, events=events, **layers)

def parse_arr(path, W, H):                # c.a(int), c.java 1089-1116
    d = open(path, 'rb').read()
    header = d[:20]                       # [19, 1 x 19] - skipped by the game
    rooms_per_mission = (W // ROOM) * (H // ROOM)   # decompiled "W/7*H/7" == (W/7)*(H/7)
    rec = 19
    nmis = (len(d) - 20) // (rooms_per_mission * rec)
    assert 20 + nmis * rooms_per_mission * rec == len(d)
    missions = []
    for m in range(nmis):
        rooms = []
        for r in range(rooms_per_mission):
            b = d[20 + (m * rooms_per_mission + r) * rec:][:rec]
            pairs = [(b[5 + 2 * k], b[6 + 2 * k]) for k in range(6)]
            rooms.append(dict(exits=list(b[0:4]),          # [down,left,up,right]
                              max_alive=b[4],
                              spawns=[p for p in pairs if p[0]],
                              unused17=b[17],
                              event_general=b[18]))
        missions.append(rooms)
    return dict(header=list(header), missions=missions, rooms_per_mission=rooms_per_mission)

def missions_for_area(data_dir, area_id): # ag.C() 1043-1062, e.bi() 3569-3603
    m = open(os.path.join(data_dir, 'mission.arr'), 'rb').read()
    s = open(os.path.join(data_dir, 'sideinfo.arr'), 'rb').read()
    o = 38 * area_id + 10
    name = m[o:o + 30].split(b'\0')[0].decode('latin1')
    du, dv = m[o + 36], m[o + 37]
    out = []
    for k in range(dv):
        r = s[11 * (du + k) + 11:][:11]
        out.append(dict(ruler=r[0], start=(r[1], r[2]), recolor=r[3], target_general=r[4],
                        on_success=r[5], on_fail=r[6], gold_mul=r[7], par_time=r[8], level_bonus=r[10]))
    return name, out

def ascii_map(mp, starts=(), events=()):
    W, H = mp['W'], mp['H']
    rows = []
    for y in range(H):
        line = []
        for x in range(W):
            k = y * W + x
            a, ob = mp['attr'][k], mp['object'][k]
            ch = '#' if a & 1 else ('^' if a & 2 else '.')
            if ob: ch = 'o'
            if (x, y) in events: ch = 'A'
            if (x, y) in starts: ch = 'S'
            line.append(ch)
        rows.append(''.join(line))
    return rows

if __name__ == '__main__':
    D = sys.argv[1]
    imgtile = read_scr(os.path.join(D, 'imgtile.scr'))
    mdat = read_scr(os.path.join(D, 'mdat_QVGA.scr'))
    edat = read_scr(os.path.join(D, 'edat.scr'))
    for mid in range(1, 46):
        mp = parse_map(os.path.join(D, mdat[mid - 1]))
        ar = parse_arr(os.path.join(D, edat[mid - 1]), mp['W'], mp['H'])
        name, mis = missions_for_area(D, mid)
        assert len(mis) == len(ar['missions'])
        print(f"map {mid:2d} {name!r:18} {mp['W']:2d}x{mp['H']:<2d} rooms {mp['W']//7}x{mp['H']//7} "
              f"missions={len(ar['missions'])} events={len(mp['events'])}")
    sel = int(sys.argv[2]) if len(sys.argv) > 2 else 1
    mp = parse_map(os.path.join(D, f'{sel}.MAP'))
    name, mis = missions_for_area(D, sel)
    for y, row in enumerate(ascii_map(mp, {m['start'] for m in mis}, {(e['x'], e['y']) for e in mp['events']})):
        print(f'{y:2d} {row}')
```

## 5. Рух, камера, колізія — конкретні числа

### 5.1 Координати
* Світові пікселі. Тайл 27 px. «Якір» сутності — точка біля ніг: при спавні `x = tx·27+12`, `y = ty·27+20` (c.java:935-936, ag.java:892-893).
* Тайл гравця: `(x/27, (y−6)/27)` (c.java:1119-1120).
* Напрямки (індекс 0..7): **0 вниз, 1 вниз-вліво, 2 вліво, 3 вгору-вліво, 4 вгору, 5 вгору-вправо, 6 вправо, 7 вниз-вправо**. Кроки `ae.aw = {0,-5,-6,-5,0,5,6,5,6}`, `ae.ax = {6,5,0,-5,-6,-5,0,5,0}` (ae.java:188-190). 8→4 для анімації: `ae.aT = {0,1,1,1,2,3,3,3}` (вниз, вліво, вгору, вправо).

### 5.2 Камера / в'юпорт
* `cb = (9,9)` тайлів, `cc = ((9·27−240)>>1, (9·27−243)>>1) = (1,0)` (ag.java:2100-2107).
* В'юпорт на екрані: `(db,dc) = (0,16)`, розмір `bY = 240×243` (ag.java:879-882) → область карти `y = 16..259`; нижня панель 61 px (`259..320`).
* `cd = ((bx−1)/7)·7 + 4 − 4 = 7·rx`, `ce = 7·ry` (ag.java:1030-1031): вікно = кімната `rx,ry` (тайли `7rx+1..7rx+7`) + кільце по 1 тайлу.
* `ca = (cd·27 + 1, ce·27 + 0)`; екранна точка = `world − ca + (0,16)`.
* Камера **ніколи не рухається** всередині кімнати.

### 5.3 Межі кімнати і перехід (ar.b 834-865, ar.X 867-888, ar.k 1892-1932)
* Межі по осі: `B[k] = 27 + 189·k` (k = 0..10; таблиця `{18,144,…}·3/2`).
* Якір гравця/ворога затиснутий у `x ∈ [B[rx]+12, B[rx+1]−12]`, `y ∈ [B[ry]+10, B[ry+1]+10]` → x ∈ [39, 204], y ∈ [37, 226] + 189·(rx, ry). (Бокс по X точно в інтер'єрі; по Y зсунутий вниз на 10 px — заходить у рамку.)
* Вихід дозволено тільки коли `co==1` і `cn<0` (стрілки вже показані) і відповідний `a[dir]` = 1. Порушення межі в напрямку виходу → `cp`, `eP` змінюється, `bV=4`.
* `k()`: `cd/ce ± 7`, перезавантаження кімнати (`bd.a(9,9,cd,ce,0)`), гравець затискається в нову кімнату (з'являється біля краю, зсув ≈24 px), за **1 кадр** `bV=3`, `do++`, `co=2,cn=1` (→ «Stage N»). Плавного скролу немає (`cm += 6` одразу перевищує поріг 6).

### 5.4 Ввід і рух гравця (c.i 1663-1919)
* Клавіші: `UP/2 → 4`, `LEFT/4 → 2`, `RIGHT/6 → 6`, `DOWN/8 → 0` (тільки 4 напрямки вводу; діагоналі гравець не вводить).
* Лише **події натискання** (`keyPressed`, немає `keyReleased/keyRepeated`). Логіка при `e[0] < 2` (стоїть/йде):
  * подвійне натискання (той самий напрям є в `cs[1..2]`, а при `dh ≥ 3` — у `cs[1..3]`, ar.e() 759-767) → **ривок** `e=2`;
  * той самий напрям, що й поточний `cz.c` → перемикання ходьба↔стоп (`e = (e+1)&1`);
  * інший напрям → поворот і ходьба `e=1`.
* Ходьба продовжується **безкінечно**, доки не натиснути знову / не вдаритися (анімація ходьби зациклена, c.java:1765-1769).
* Швидкість: ходьба 6 px/тік (діаг. 5); ривок `<<2` = 24 px/тік, анімація ривку 3 тіки (`ae.D`) ≈ 72 px; атаки 3..8 рухають на 1/3 кроку (2 px); відкидання при ударі (`e=9`) 24 px/тік `R` тіків назад, потім 3/4 кроку.
* Анімації гравця (`cz.ab[state][dir][tick]`, ag.java:2069-2099): idle `ae.B` (1 кадр: 1/4/7/10), walk `ae.C` (0,1,2,1 — 4 тіки на цикл), dash `ae.D` (41..44 × 3), hurt `ae.E`. Значення ≥200 (222) — кінець послідовності; кадри ≥180 — невидимі (блимання).
* Тік гри: `ae.aQ[dh] = {250,180,120,90,50}` мс (ag.java:748), `dh=2` за замовч. (ag.java:857) → ~8.3 тіка/с, ходьба ≈ 50 px/с, кімната (189 px) ≈ 3.8 с.
* Інші клавіші на карті: `5/FIRE` атака (комбо до 3, якщо минуло < 7 тіків, c.java:1787-1796), `1,3,7,9,0` — скіли `cz.V[0..4]`, `*`/`#` — швидкі предмети, права софт `-7` — пауза, ліва софт `-6` — пропуск діалогу.

### 5.5 Колізія
* **Тайлова** (`ar.a(h,step,dir)` 769-815): точки перевірки
  * вліво: `x+step−12`, рядки `(y−20)/27` і `(y+6)/27`; вправо: `x+step+12`;
  * вгору: `y+step−20`, колонки `(x−12)/27` і `(x+12)/27`; вниз: `y+step+6`.
  * Заблоковано, якщо `attr&1` або `objects != 0`. Крок зменшується на 1 px до прохідного (може стати 0).
* **Діагональ** (`ar.a(h,dx,dy,dir,idx)` 1060-1115): якщо вільна лише одна вісь — ковзання по ній зі швидкістю `u()` (5 → 7 px).
* **Автообхід** при ходьбі в стіну по кардиналі (`ar.c` 890-1014): якщо наступний тайл вільний — вирівнювання до `x=tile·27+8` (≤3 px/тік) або `y=tile·27+20` (≤4 px/тік); інакше пошук вільного «проходу» до 5 тайлів убік по поточному рядку/колонці (обидва — ближчий за позицією в тайлі) і крок у той бік.
* **Кламп кімнати** (§5.3) завжди після тайлової колізії.
* **Юніт-юніт**: `ar.a(h,dx,dy,idx)` 1155-1194 намагається не підпускати ближче 27×27, але результат `t()` відкидається (рядки 1165, 1180) → фактично **сутності проходять одна крізь одну** (впевненість середньо-висока; див. §9).

### 5.6 Вороги (коротко, для карти)
* Мечник 201/203: рішення кожні 6 тіків (`s`), ходьба 6 px/тік, повільний крок 2 px; у радіусі 90 px частіше йде до гравця; атакує в радіусі 45 px (`Y()` 1216-1278). 203 = 3 фігури, колізія розширена ±10 px (1429-1499), за вбивство +3 у лічильник.

## 6. Рендеринг

### 6.1 Шари і що де лежить
1. **ground** (шар 0) і **overlay** (шар 1) → один раз на кімнату пререндеряться в `ct[7]` (c.java:1301-1311) — 9×9 тайлів у (col·27, row·27).
2. **objects** (шар 2) — не в `ct[7]`; щокадру малюються лише в брудних тайлах (`ar.l()` 1971-1983). Розбитий об'єкт: шар 2 обнуляється (`ar.W()` 663-672), 12 тіків блимає кадр `v+1`, потім зникає і може випасти предмет.
3. **сутності** (тінь `shadow_01` 27×11 під кожним, тіло, голова, зброя, ефекти) у порядку y (painter, `ar.h()` + вставка гравця в `c.e()`).
4. **foreground**: overlay-тайли з `attr&2` перемальовуються поверх спрайтів у брудних тайлах (`c.l()`).
5. Стріли, ефекти, предмети; HUD (абсолютні координати) поверх усього.

### 6.2 Порядок кадру (`bV==3`)
`ar.a()` → `c.i()` [стирання старих прямокутників копіюванням з `ct[7]`; ввід; оновлення] → `ag.L()` → `ar.b(0)` → `c.c()`:
`ar.l()` (об'єкти в брудних тайлах минулого кадру) → очистити `eE` → `ar.m()` (предмети, блимання об'єктів) → `c.e()` (сутності, позначають `eE`) → `c.m()` (ефекти) → `c.l()` (foreground) → `c.k()` (стріли) → `c.b()` (рамка HUD) → `ar.n()` (вміст HUD) → `c.j()` (стрілки виходу при `co==1`) → `ar.aC()`.
Повний кадр (`ck==1`): `ag.K()` блит усього `ct[7]` + всі `eE=1`.
Для Godot уся система dirty-rect **не потрібна**: TileMapLayer + y-sort + окремий шар foreground з вищим z.

### 6.3 Кеш тайлів (c.java:1221-1299)
Прохід 0: `cJ` для ground+overlay вікна → завантажити PNG → намалювати в `ct[7]`. Прохід 1: скинути, `cJ` для overlay з `attr&2` і для об'єктів (`v` та `v+1`), створити `cA` (тільки в межах вікна 9×9, тож і для кільця). Обмеження — пам'ять телефона; у Godot достатньо одного атласу.
