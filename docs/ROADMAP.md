## 2. Чому «1:1 з Java» і чому це реально

Перевірено по коду:
- **Уся графіка гри проходить через один клас `x.java`.** Він має 8 примітивів: `drawImage` (anchor TOP|LEFT), `clipRect`/`setClip`, `fillRect`, `drawRect`, `drawLine`, `setColor`, плюс бітмап-шрифт (`g.java`, `0_font.png`). `drawRegion` і трансформацій немає. Тому прокладка під pygame займе приблизно 150 рядків.
- **Один ігровий цикл** (`ag.run`, `ag.java:708-760`). Тік: 120 мс у меню, 50–250 мс у бою (опція Speed). Обробляється лише `keyPressed`. Це переноситься в pygame-цикл дослівно.
- **Звук:** `k.java` (MIDI `snd0–2`, WAV `snd3–16`) → `pygame.mixer` + OGG.
- **Збереження:** 3 `RecordStore` → файли на ПК / `localStorage` у браузері.
- **Мережа** — лише `v.java` (TCP-сокет) → замінюється офлайн-бекендом.

Отже методи переносяться як є, з тими самими іменами, і перевіряються на даних. Перепридумувати екрани (як довелося в Godot) не треба.

## 3. Правила для всіх етапів

1. **Спершу дослівно, потім красиво.**
   - Метод `ag.C()` стає `ag.C()` у Python, з коментарем `# ag.java:1043-1062`.
   - Перейменування й рефакторинг — лише після того, як фіча працює і покрита тестом.
2. **Семантика Java важливіша за звичний Python.** Ділення і `%`, переповнення `int`, `byte` зі знаком, `>>>`, від'ємні індекси, fall-through у `switch`, аліасинг посилань. Чекліст — `plans/PHASE_1_FOUNDATION.md` §2.
3. **Артефакти декомпілятора** виправляються свідомо й позначаються `# DECOMP-FIX:`. Реєстр — `PHASE_1` §3.
4. **Баги оригіналу** мовчки не виправляються: прапорець у `config.py` + коментар `# ORIG-BUG:`.
5. **Кожен етап закінчується грабельним станом** і тестами: pytest + headless-скріншоти.
6. **Godot-файли не чіпаємо.** Python-код живе в `pyport/`, ресурси читає з кореня проєкту.

## 7. Ризики

- **Тонкощі семантики Java** при дослівному перекладі дають помилки, які видно лише в грі. Захист: чекліст, тести на даних, headless-скріншоти, порівняння з емулятором.
- **Браузер (pygbag):** збереження, звук і швидкість завантаження перевіряємо на етапі 0, а не в кінці.
- **Неоднозначні місця декомпіляції.** Список — у `analysis/*` (розділи «Невідомі»). Їх треба перевірити в емуляторі.
- **Еталон для порівняння.** Потрібні скріншоти/відео оригіналу з KEmulator (у вас є `kemulator.cfg`).
- **Місце на диску.** На комп'ютері замало вільного місця, тож Claude не може запускати команди прямо в цій папці й переносить файли туди-назад. Це повільніше. Звільнивши ~17 ГБ, ви дасте змогу працювати напряму.
- **Права.** Код і ресурси належать Gamevil. Для особистого користування й вивчення — нормально; публічне розповсюдження порту потребує дозволу правовласника.

## 8. Структура `pyport/` (план)

```
pyport/
  main.py              # вхід для ПК і браузера (async-цикл)
  config.py            # масштаб, швидкість, прапорці ORIG-BUG
  pow/
    midp/              # прокладка J2ME
      graphics.py      #   Image, Graphics (= x.java), шрифт
      canvas.py        #   цикл ag.run, клавіші телефону
      rms.py           #   RecordStore → файли / localStorage
      media.py         #   Player → pygame.mixer
      jrandom.py       #   точна копія java.util.Random
      jint.py          #   семантика int/byte/ділення/зсувів, JArray
    data/              # завантажувачі: scr, dtable(.arr), maps, sp3, campaign, items
    game/              # дослівно перенесені класи: ag.py, e.py, c.py, ar.py, l.py, ae.py, n.py, …
    live/              # офлайн Gamevil Live (замість as/v/u/b/ab/s)
  tools/               # перевірка ресурсів, MIDI→OGG, скріншот-раннер
  tests/               # pytest: дані, формули, скріншоти, сценарії вводу
  CLAUDE.md            # правила для Python-частини
```

## 10. Як це лягає на workflow агентів

Ланцюжок той самий (PM → BA → Tech Lead → Developer → Reviewer → QA), але:
- **PM** бере специфікації з `docs/analysis/`: Java там уже розібрано з номерами рядків.
- **Tech Lead** нарізає таски прямо з таблиць `docs/plans/PHASE_*.md`.
- **Developer** переносить Java дослівно за правилами `pyport/CLAUDE.md`.
- **Reviewer** звіряє з Java за чеклистом семантики (`PHASE_1` §2). Хук у `.claude/settings.json` треба розширити на `.py`.
- **QA** запускає `pytest` і порівнює скріншоти.

Оновлення `CLAUDE.md` та визначень агентів — таск етапу 1.
